# 日次オートメーション — MesLang 改善

Cursor Automations などから **毎日 1 回** このリポジトリを改善するための指示書です。

## オートメーション設定（人間が一度だけ）

1. Cursor の Automations でこのリポジトリを対象に日次スケジュールを作成
2. プロンプトに、下記「エージェントへの指示」を貼る（または本ファイルを読むよう指示）
3. 成果は PR で出す。直接 main へ大きな破壊を押し込まない

推奨モデル: リポジトリ理解と仕様執筆が得意なもの。

## エージェントへの指示（プロンプト本体）

```
あなたは MesLang（実験的な軽量メディア記述言語）の日次メンテナです。

必読:
- README.md
- docs/philosophy.md
- docs/roadmap.md
- docs/spec/（現行仕様）
- docs/decisions/（ADR）
- automation/DAILY.md の「今日の進め方」
- AGENTS.md

目的:
音声作品＝漫画を最優先に、記号速記と字句デコレーションを両立する仕様を、小さく確実に前へ進める。

今日やること（どれか1つを深く、または小さく2つ）:
1. 仕様の穴を1つ埋める（曖昧な文を決定 or ADR 化）
2. examples/ に現実的なサンプルを1つ追加・改善
3. 参照パーサ packages/meslang-ref のテストを1ケース増やす
4. AI 向けガイド（docs/spec/04-ai-reading.md）の実務プロンプトを磨く
5. 旧 Mes 互換の論点を ADR 下書きする

制約:
- 哲学（思考を阻害しない / 原稿と台本の分離 / 必須情報ほぼゼロ）を破らない
- コアを肥大化させず、メディア固有はプロファイルへ
- 破壊的変更は ADR 必須。CHANGELOG に一行残す
- 未使用の大きなフレームワークや製品級パーサを持ち込まない
- コミットして PR を出す。説明は短く「何が良くなったか」を書く

終わったら:
- 明日の候補を docs/roadmap.md か automation/backlog.md に1〜3個追記
```

## 今日の進め方（ローテーション）

## 完了の定義（その日の PR）

- [ ] 仕様かサンプルかテストの、目に見える差分がある
- [ ] 哲学に反する変更がない
- [ ] ADR が必要な変更なら追加済み
- [ ] CHANGELOG 更新
