# 音声作品の見本

`profile: audio`（または省略時の既定）の原稿です。  
`$`（音）と `!`（位置）の書き方の目安は、[語彙ガイド](../../docs/spec/03-media-profiles.md#音と位置の語彙ガイドよく使う書き方) にまとめています。  
`!` は音の位置にも話者の位置にも使えます（`$` なしでも可 → [用語集](../../docs/spec/05-glossary.md#音の位置と話者の位置まぎらわしいことば)）。  
字幕や尺が必要なときだけの `&` も、同じ節に短く書いてあります（漫画の `*間` との呼び分けは [用語集](../../docs/spec/05-glossary.md#タイミングとビートまぎらわしいことば)）。  
絵がないので `%`（コマ／カット）はふつう使いません → [用語集（コマとカット）](../../docs/spec/05-glossary.md#コマとカットまぎらわしいことば)。

## station.mes — 駅前の二人

ソース: [station.mes](./station.mes)

オープニングの会話に、BGM・環境音・左右・遠近のメモを足した見本です。  
セリフの流れは止めず、音まわりだけあとから厚くしています。  
かぎかっこ速記（`@にか[焦り]` / `@にか[思索][ヒソヒソ]`）は、音声では 2 個目が **声質** になります。

二場面目「改札を出て」では、同じピースに `$`（聞こえる音）・`!`（位置）・`&`（字幕／尺）と、話者の `:声質`（属性またはかぎかっこ 2 個目）が並ぶ例を置いています。  
場のアナウンスは `$`、いま話している人の声の出し方は `:声質`、という分け方の練習用です。

三場面目「ランチへ」では、**音だけの間**（セリフのないピース。`$` / `!` / `&` / `#` だけ）で信号待ちの拍を置いてから、また会話に戻ります。  
漫画の **無言コマ** と同じく、音だけの拍も原稿の一部です。同じ信号待ちの拍を漫画側で置いた例は [station-two-pages.mes](../manga/station-two-pages.mes) の2ページ目 `%4` です。  
呼び分けは [用語集](../../docs/spec/05-glossary.md#セリフのない間音だけの間--無言コマ) をどうぞ。

四場面目「店の前」では、入り口に着いてドアチャイムが鳴るところまでを置いています。  
漫画ネーム見本では `%8` 外注ぎのあとに `%9` 入店（[station-name.mes](../manga/station-name.mes)）が続き、同じ **到着の拍** を音声側でも厚くした例です。  
呼び分けは [用語集（到着の拍）](../../docs/spec/05-glossary.md#到着の拍まぎらわしいことば) をどうぞ。

五場面目「席について」では、**到着の拍のあと**の店内を置いています。  
戸が閉まり、店内 BGM に切り替わり、席へ案内されるところです。入り口までの拍（「店の前」／漫画 `%8`–`%9`）とは別セクションです。  
漫画側の同じ区切りは [station-name.mes](../manga/station-name.mes) の `%10` です。店内の続きの **ひとつ**（席について）です。

六場面目「注文」では、席について **さらにあと** の拍です。席の店員が来て、いつもの海鮮丼を頼みます。  
入り口の外注ぎ（漫画 `%8` の `@店員`）と話者名は同じでも、席の店員はふつうのセリフです。漫画側の同じ区切りは [station-name.mes](../manga/station-name.mes) の `%11` です。cafe-pose の **任せたあと**（客どうしで注文を決める）や **任せたあとの無言**（同見本 `%11`。店員は来ない）とも別見本です。

七場面目「丼が来る」では、注文を取った **さらにあと** の拍です。同じ `@店員` が丼を運んできます。取る拍と運ぶ拍は別です。漫画側の同じ区切りは [station-name.mes](../manga/station-name.mes) の `%12` です。  
「席について」と「注文」と「丼が来る」をあわせた総称が **店内の続き** です（漫画はいま `%10`–`%12`）。  
呼び分けは [用語集（到着の拍と店内）](../../docs/spec/05-glossary.md#到着の拍と店内まぎらわしいことば) / [用語集（店内の続きと注文）](../../docs/spec/05-glossary.md#店内の続きと注文まぎらわしいことば) / [用語集（任せたあとと注文を取る）](../../docs/spec/05-glossary.md#任せたあとと注文を取るまぎらわしいことば) をどうぞ。  
駅前とカフェを横並びに見たいときは [用語集（見本の場面対応）](../../docs/spec/05-glossary.md#見本の場面対応まぎらわしいことば) をどうぞ。

### 属性のつき先（短い対比）

`:key value` は **直前のデコレーターの直後** に書きます。ピース先頭だけに置くと、属性にならずセリフ行として残ります。

```mes
# 属性になる（@ の直後）
@にか :表情 微笑
こんにちは

# 属性にならない（孤立した :key → セリフに残る）
:表情 微笑
こんにちは
```

くわしくは [用語集（属性のつき先）](../../docs/spec/05-glossary.md#属性のつき先まぎらわしいことば) / [用語集（行の種類と属性の続き）](../../docs/spec/05-glossary.md#行の種類と属性の続きまぎらわしいことば) をどうぞ。

### 声質のつき先（短い対比）

`:声質` は **話者（`@`）の直後** です。`$` や `!` のあとに置くと、音や位置に付いて話者には届きません。

```mes
# 声質になる（@ の直後）
@にか :声質 ヒソヒソ
$雑踏
あ、キタキタ。

# 声質にならない（$ に付く）
@にか
$雑踏 :声質 ヒソヒソ
あ、キタキタ。
```

旧 Mes の `$ヒソヒソ声` を移すときも、音の行に `:声質` を足すのではなく `@` の直後へ。`$` のまま残すのは誤りではありません。  
くわしくは [用語集（音・声質と属性）](../../docs/spec/05-glossary.md#音声質と属性まぎらわしいことば) をどうぞ。

### 話者と音は、そのピースだけ

空行のあとが次のピースです。前の `@` や `$BGM` はコピーされません。

```mes
@にか
$BGM 夕方の駅（控えめ）
待たせたな。
今日は奢る。

海鮮丼にしよう。
```

下のセリフは、話者なし・音メモなしです。誤りではありません。  
同じ人として残すなら `@` をもう一度、BGM を続けるなら `$BGM 夕方の駅（続く）`、止めるなら `$BGM 夕方の駅（止む）` とそのピースに書きます。  
呼び分けは [用語集（ピースをまたがない）](../../docs/spec/05-glossary.md#ピースをまたがないまぎらわしいことば) をどうぞ。  
旧 Mes の `--compat` も、話者や音を次のピースへ継ぎません。

### セリフ文字数を数える（任意）

```bash
cd packages/meslang-ref
npm run count -- ../../examples/audio/station.mes
```

空白を除いたセリフだけの合計です。記号行（`$` や `#` など）は数えません。句読点は数えます（ヘッダーの `$ignore_char` では外れません）。  
AI に目安だけ聞いて照合するときは、[セリフ文字数の照合](../../docs/spec/04-ai-reading.md#セリフ文字数の照合音声) のひな形をどうぞ。

## 旧 Mes 取り込みの三段階

- [mes-import-before.mes](./mes-import-before.mes) … 取り込み前。ヘッダー `$title`、章らしい `#オープニング`、行頭 `○` / `◯`、旧流儀の `$ヒソヒソ声`、場の `$` / `!`、ことばの間 `&少し間を置いて`（`*` は使わない）、行頭 `//`、途中の `//`（かぎかっこ内と `$` 行）、空白4つのセリフ速記、全角空白のセリフ行、二重かぎ `にか『二年ぶりだね。』`、混ぜ行の `@にか「記号と糖衣は混ぜない。」`
- [mes-import-compat-only.mes](./mes-import-compat-only.mes) … **機械変換だけ**（`--compat` / `rewriteMesCompat`）。柱は `#` になったが、`#オープニング` も `$ヒソヒソ声` もまだ人手前
- [mes-import-after.mes](./mes-import-after.mes) … 人手のあと。章を `==` に、話者の声だけ `:声質` へ。場の音・位置・`&` はそのまま。先頭は `@名前`、途中のセリフは `名前「」`、末尾は空白4つのまま（混ぜてよい例）。全角空白の行は糖衣しない実例のまま

機械が直すのは行頭の `○` / `◯` → `#` だけです。似た形の `〇`（漢数字のゼロに近い形）は柱ではないので直しません。  
`#オープニング` を `==` にするか、`$ヒソヒソ声` を `:声質` へ移すかも人の判断です（compat-only と after を見比べると分かります）。  
行頭の `//` はコメントアウトです。機械は触らず、パース時に読み飛ばします。途中の `//` は旧 Mes と違い、残りです。見本はかぎかっこの中と `$` 行に置いてあります（閉じかぎのうしろに置くと `名前「」` 糖衣がかかりません → [用語集（コメントアウトは行頭だけ）](../../docs/spec/05-glossary.md#コメントアウト行頭だけまぎらわしいことば)）。  
呼び分けは [用語集（取り込みの三段階）](../../docs/spec/05-glossary.md#取り込みの三段階機械変換と人手) をどうぞ。  
`名前「セリフ」` は DoFlat が `@` へ直すので、原稿をすべて `@名前` に揃える必要はありません（after 見本は `@`・`名前「」`・空白4つを混ぜています）。  
半角空白4つやタブも同じ速記ですが、**全角空白では糖衣しません**（見本の末尾がその実例 → [用語集（速記の空白）](../../docs/spec/05-glossary.md#速記の空白半角と全角まぎらわしいことば)）。  
糖衣するのは **角かぎ「」** だけです。見本の `にか『二年ぶりだね。』` は二重かぎのまま残り、話者にはなりません（[用語集（セリフのかぎ）](../../docs/spec/05-glossary.md#セリフのかぎまぎらわしいことば)）。  
空白4つ（またはタブ）も同じ速記です。`--compat` は触りません → [用語集（速記の橋渡し）](../../docs/spec/05-glossary.md#速記の橋渡しかぎかっこタブ空白4つまぎらわしいことば)。  
同じ行の `@名前「」` は糖衣しません。before / compat-only の `@にか「記号と糖衣は混ぜない。」` がその例で、after では `@にか` とセリフ行に分けています → [用語集（糖衣と行頭記号）](../../docs/spec/05-glossary.md#糖衣と行頭記号まぎらわしいことば)。  
`&少し間を置いて` は取り込み後も `&` のままです（漫画の `*間` へ直しません → [用語集](../../docs/spec/05-glossary.md#タイミングとビートまぎらわしいことば)）。  
手順は [06-mes-compat.md](../../docs/spec/06-mes-compat.md)、`$` と `:声質` の分け方は [音声プロファイル](../../docs/spec/03-media-profiles.md#音声質ト書きの分け方) をどうぞ。  
ヘッダーの `$title` は変数で、本文の `$音` とは別ものです（[コア仕様](../../docs/spec/01-core.md#ヘッダーの--と本文の--は別もの) / [用語集](../../docs/spec/05-glossary.md#音声質ヘッダー変数まぎらわしいことば)）。  
`$default_charactor_name=名前` のような旧設定はメモとして残りますが、`@` の無いセリフの話者にはなりません。記号の入れ替え（`$deco_*`）や、句読点を集計から外す指定（`$ignore_char`）も動きません → [用語集（既定の話者は埋めない）](../../docs/spec/05-glossary.md#既定の話者は埋めないまぎらわしいことば)。  
`!` の二用法（音の位置／話者の位置）は [用語集](../../docs/spec/05-glossary.md#音の位置と話者の位置まぎらわしいことば) をどうぞ。

## AI に頼むとき

台本化・音声原稿の下書き・旧 Mes 取り込みの手伝いは、[AI 向けガイド](../../docs/spec/04-ai-reading.md#音声台本化) のひな形をコピーしてください。  
ひな形のなかには、駅前とカフェを「注文」ということばだけで同一視しない注意（[見本の場面対応](../../docs/spec/05-glossary.md#見本の場面対応まぎらわしいことば)）もあります。  
行頭だけの `:表情` は属性ではなくセリフ行です（[行の種類と属性の続き](../../docs/spec/05-glossary.md#行の種類と属性の続きまぎらわしいことば)）。  
ヘッダーに `profile` が無くても誤りではありません（取り込み前／機械変換直後見本がその例です → [用語集（ヘッダーの縁）](../../docs/spec/05-glossary.md#medo-の形チェックの縁まぎらわしいことば)）。空配列は通りますが、中身の型が違うと弾きます（[配列の中身](../../docs/spec/05-glossary.md#medo-の形チェックの縁まぎらわしいことば)）。  
`--validate` が通っても、声質が話者にあるとは限りません（通った＝声質が話者にある、ではない → [用語集（音・声質・ヘッダー変数）](../../docs/spec/05-glossary.md#音声質ヘッダー変数まぎらわしいことば)）。  
セリフだけの下書きも形としては通ります（[原稿の必須と箱の必須](../../docs/spec/05-glossary.md#原稿の必須と箱の必須まぎらわしいことば)）。配列の箱に `{}` を置くと弾きます（[配列とオブジェクト](../../docs/spec/05-glossary.md#medo-の形チェックの縁まぎらわしいことば)）。  
セリフ文字数の照合はツールの `--count` が本命で、AI 用のひな形は [セリフ文字数の照合](../../docs/spec/04-ai-reading.md#セリフ文字数の照合音声) にあります。
