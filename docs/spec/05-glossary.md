# 用語集（v0）

仕様・ADR・見本・参照パーサで使うことばをそろえます。  
英語は Medo / コード上の識別子、日本語は文書と著者向けの呼び名です。

## 三層（原稿 / Medo / カット表）

MesLang まわりの話は、だいたい次の三層に分かれます。  
「どこまでが人が書くものか」「どこからがツールの仕事か」を迷ったときに戻ってください。

| 層 | 呼び名 | ひとことで | 例 |
|----|--------|------------|----|
| 1 | **原稿**（MesLang） | 人が書く、軽いテキスト | `.mes` 見本、ネーム用途の記述 |
| 2 | **Medo**（中間データ） | ツールや AI が共有する JSON | `medo/0.0`、参照パーサの出力 |
| 3 | **カット表**など（二次出力） | 読みやすさのための整形 | `conte-table/0.0`、台本・完成ネーム・字コンテ |

流れはいつも同じです。**原稿 → Medo → 二次出力**。  
カット表は層3の代表例です（[07-conte-table.md](07-conte-table.md) / [ADR 0008](../decisions/0008-conte-table-secondary.md)）。台本や完成ネームも同じ層に置きます。

- **二次出力** … Medo などから組み立てた、読みやすさのための成果（カット表・台本・完成ネーム・字コンテ概要など）
- **二次成果物** … 原稿の外に置くもの全般。二次出力に加え、見本用の参考画像なども含みます（[ADR 0004](../decisions/0004-manga-reference-images.md)）
- **二次ツール** … それらをつくる側（パーサの先、組版、絵コンテ表など）

著者向けの文書では、層1を **原稿**、層2を **Medo**（初めて出すときは「中間データ（Medo）」）、層3を用途に応じて **カット表 / 台本 / ネーム / 字コンテ（二次出力）** と呼びます。README の「三つの層」も同じ分け方です。

## 構造

| 日本語 | 英語 / ID | 意味 |
|--------|-----------|------|
| ヘッダー | header | `----` より前。`profile` や `title` など、任意のメタ情報。`$key value` 形も可（本文の `$音` とは別） |
| ボディ | body | `----` より後の本文 |
| セクション | section | `==` 見出しで区切るまとまり（章・ページなど） |
| ピース | piece | 空行で区切る、いちばん小さな意味のまとまり |
| セリフ | dialogue | ピース内の、記号でも属性でもない行 |
| 中間データ | Medo | ツールが吐き出す構造化 JSON（`medo/0.0`）。上の三層の **層2** |
| 形チェック | validate / schema | Medo やカット表の **箱の名前と型** が揃っているかの確認（`--validate` / `--conte --validate`）。話の良し悪しや不足は見ません（[schema/medo.schema.json](../../schema/medo.schema.json)）→ [呼び分け](#形チェックと目視まぎらわしいことば) |
| kind | kind | Medo 上の記号の種類 ID（`character` / `comment` など）。著者向け文書では下表の日本語を優先 |

## 形チェックと目視（まぎらわしいことば）

「通った／通らない」と「足りている／足りない」は別の話です。  
迷ったら、「機械が JSON の箱を見ているのか／人が中身を読んでいるのか／AI が不足を洗っているのか」で振り分けてください。

| 使ってよい語 | だれ | 意味 | 例 |
|--------------|------|------|----|
| **形チェック** | ツール | Medo やカット表の **箱の名前と型** だけを見る | `--validate` / `--conte --validate` |
| **目視** | 人 | 形チェックのあと、中身が意図どおりかを目で確かめる | [取り込み後 Medo の目視](06-mes-compat.md#取り込み後-medo-の目視任意) |
| **不足の洗い出し** | AI（または人） | 話・構図・音などに足りない情報がないかを列挙する | [AI 実務の順番](04-ai-reading.md#おすすめの実務の順番) |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 形チェック / 箱の名前と型 | 「欄の名前と型」だけを本命にする | 文書では **箱** でそろえます（schema の description も同じ） |
| 形チェック | 形チェックを「品質チェック」「良し悪しの判定」と呼ぶ | 話の良し悪しやカット割りは見ません |
| 目視 | 目視を形チェックと呼ぶ | `--validate` が通っても、柱の直し残しなどは目視の仕事です |
| 不足の洗い出し | 不足洗い出しを形チェックと呼ぶ | 足りない情報の列挙は AI／人の仕事です（ツールはしません） |

CLI の入口は README の `--validate` / `--conte --validate` です。  
結果の読み方ひな形は [AI ガイド（Medo）](04-ai-reading.md#medo-の形チェック結果の読み方) / [AI ガイド（カット表）](04-ai-reading.md#カット表の形チェック結果の読み方) です。  
カット表側の説明は [07-conte-table.md](07-conte-table.md) をどうぞ。  
Medo でよく迷う縁（**空と欠け**・**ヘッダーの縁**）はすぐ下の節、カット表の縁（番号なしの `cut: ""` など）はその次です。

## Medo の形チェックの縁（まぎらわしいことば）

Medo（`medo/0.0`）の形チェックも **箱の名前と型** だけです。  
「セリフが空」「セクションが無い」などは、品質の話ではありません。

| 使ってよい語 | 意味 | 注 |
|--------------|------|-----|
| **空のセクション列**（`sections: []`） | 本文にセクションがまだ無い | 空でも正しい。形チェックは通します |
| **空のピース列**（`pieces: []`） | そのセクションにピースが無い | 同上 |
| **空のデコレーター列**（`decorators: []`） | 記号が付いていないピース | セリフだけのピースも正しい |
| **空セリフ**（`dialogue: ""`） | 無言コマなど、セリフ箱が空 | 空文字も正しい。品質不足とは言いません |
| **空の attrs**（`attrs: {}`） | 属性が無いデコレーター | 値が無いことと、箱が無いことは別です |
| **空と欠け** | 空の値は正しい。必須箱そのものが無いのは弾く | `dialogue: ""` は通る。`dialogue` キーなしは弾く。`rawMark: ""` は通る。`rawMark` 欠けは弾く |
| **ヘッダーの縁** | 空の `header`、`profile` なし、追加の文字列キーは正しい | 未知の `profile` と空文字の `profile: ""` は弾く。値は文字列だけ |
| **余分なキーを弾く** | schema に無い箱名（ピース直下の `attrs` など） | 手組み JSON の打ち間違い検知向け |
| **kind `unknown`** | 手組み Medo の逃げ道 | 参照パーサの通常出力ではない（表に無い行頭はセリフへ残す） |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 空の配列・空セリフは正しい箱 | 「空＝形チェック失敗／未完成」と形チェックが言う | 話・構図・音の不足は目視・不足洗い出しの仕事です |
| 空の値と、箱の欠けは別 | 「空文字＝キーなし」と同一視する | `""` / `[]` / `{}` は箱がある。キーなしは弾きます |
| ヘッダーに `profile` が無くても通る | 手組みで `profile` が無いのを誤りにする | 参照パーサは **原稿** を読むとき `audio` を補います。手組み JSON では無くて構いません。書くなら `audio` / `manga` / `anime` / `vn` / `unknown` のどれか（空文字は未知と同じく弾く） |
| ピース直下に attrs は無い | Medo のピースへ表情などを足すのを本命にする | attrs はデコレーター側（[属性のつき先](#属性のつき先まぎらわしいことば)） |
| `rawMark` は必須 | 記号の見た目を捨てた JSON を通す | 半角・全角はそのまま保持します。空文字は正しい箱、キーなしは欠けです |

schema は [medo.schema.json](../../schema/medo.schema.json)、結果の読み方は [AI ガイド](04-ai-reading.md#medo-の形チェック結果の読み方) です。  
漫画の `%10` など、同じコマに複数セリフがある見本も、ピースが並ぶだけで形チェックの対象です（[コマとピース](#コマとピースまぎらわしいことば)）。

## カット表の形チェックの縁（まぎらわしいことば）

カット表（`conte-table/0.0`）の形チェックは、Medo と同じく **箱の名前と型** だけです。  
「番号が空」「カメラが無い」などは、品質の話ではありません。

| 使ってよい語 | 意味 | 注 |
|--------------|------|-----|
| **番号なしカット行**（`cut: ""`） | `%` より前のピースから始まった行 | 空文字も正しい。形チェックは通します |
| **空の配列欄**（`camera: []` など） | その欄に値が無いだけ | セリフなしなら `dialogues: []` も正しい |
| **空と欠け** | 空の値は正しい。必須箱そのものが無いのは弾く | `cut: ""` は通る。`cut` キーなしは弾く。`dialogues: []` は通る。`dialogues` なしは弾く |
| **余分なキーを弾く** | schema に無い箱名 | 手組み JSON の打ち間違い検知向け |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 番号なし（`cut: ""`）は正しい箱 | 「空の cut はエラー／未完成」と形チェックが言う | 品質やカット割りは目視・不足洗い出しの仕事です |
| 空配列は正しい | 「欄が空＝形チェック失敗」 | 値が無いことと、箱の型が違うことは別です |
| 空の値と、箱の欠けは別 | 「空文字＝キーなし」と同一視する | `cut: ""` は箱がある。`cut` キーなしは弾きます |
| カット表に話者 attrs は載せない | `dialogues` に表情などを足すのを本命にする | attrs は Medo の話者側（[属性のつき先](#属性のつき先まぎらわしいことば)） |

くわしい表は [絵コンテ／カット表（形チェックの縁）](07-conte-table.md#形チェックが見る縁よく迷うところ) をどうぞ。

## 記法

| 日本語 | 英語 / ID | 意味 |
|--------|-----------|------|
| デコレーター | decorator | 行頭の記号で種類が決まる、意味付けの行（`@` `#` `$` など）→ [呼び分け](#デコレーターと行頭記号まぎらわしいことば) |
| 行頭記号 | leading mark | `@` `#` `$` など、行の先頭につける記号そのもの。**デコレーターと同じ仲間**です（同上） |
| 属性 | attr / attrs | `:key value`。**直前のデコレーター** に付きます（ピース直下の箱はない）→ [呼び分け](#属性のつき先まぎらわしいことば) |
| かぎかっこ速記 | bracket sugar | `@名前[…][…]` を属性へ直す短縮。著者向けの正称は **かぎかっこ速記**（コードでは `bracket` と呼ぶことがあります）→ [呼び分け](#かぎかっこ速記と属性まぎらわしいことば) |
| 糖衣 / 速記の橋渡し | sugar | パース前に正規の形へ直す入力の短縮（`名前「セリフ」` など）。著者向けでは **速記** で足ります |
| DoFlat | `doFlat` | その短縮を展開する処理の呼び名（参照パーサの関数名） |
| プロファイル | profile | メディアごとの記号や慣習（`audio` / `manga` / `anime`） |
| 参考画像 | reference image | 漫画サンプルのページからつくった二次画像（1ページ＝1枚）。原稿の外で、サンプルのそばに置きます（[ADR 0004](../decisions/0004-manga-reference-images.md)）。**二次成果物**です（カット表のような Medo 由来の二次出力とは別物） |

## デコレーターと行頭記号（まぎらわしいことば）

`@` や `#` の話をするとき、「デコレーター」と「行頭記号」のどちらも出てきます。  
指しているものは同じ仲間です。文書の場面で言い方をそろえるための呼び分けです。

| 使ってよい語 | どこでよく使うか | 意味 | 例 |
|--------------|------------------|------|----|
| **行頭記号** | 著者向け・AI ガイド | 行の先頭につける記号そのもの | `@` `#` `$` `%` `＾` など（[全角／半角](#全角半角の行頭記号まぎらわしいことば)） |
| **デコレーター** | 仕様の見出し・構造の説明 | その記号で始まる **意味付けの行**（値や、直後の属性も含むイメージ） | `@にか :表情 微笑` の一行 |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 行頭記号 ≒ デコレーター（同じ仲間） | 「デコレーターと行頭記号は別物」と言う | 著者向けでは **行頭記号** で足ります。見出しでは「デコレーター」も使います |
| 属性（`:key value`） | 属性を「行頭記号の一種」と呼ぶ | 属性は記号行に **付く** もの。行頭の `@` などとは別です → [かぎかっこ速記と属性](#かぎかっこ速記と属性まぎらわしいことば) |
| kind / `rawMark`（Medo） | 著者向けの本命に「マーク」だけを据える | Medo 側の箱の話です。人が書くときは記号の日本語名（話者・ト書きなど）を優先 |

くわしい表は [デコレーターと属性](02-decorators.md) をどうぞ。

## かぎかっこ速記と属性（まぎらわしいことば）

表情・姿勢・吹き出し・声質などは、**属性**でも **かぎかっこ速記** でも書けます。  
行き先は同じです。好きなほうで書いてください。どちらも **原稿の書き方** で、二次出力ではありません。

| 使ってよい語 | 書き方 | 意味 | 見本 |
|--------------|--------|------|------|
| **属性**（`:key value`） | `@にか :表情 困り` | キー名が目に見える。あとから足しやすい | [cafe-pose.mes](../../examples/manga/cafe-pose.mes) の `%8`（`:吹き出し 心の声`）・`%9`（ふつうのセリフに戻る）・`%10`（任せたあと） |
| **かぎかっこ速記** | `@にか[困り][前のめり]` | さっと書く短縮。パース時に属性へ直る | [station-name.mes](../../examples/manga/station-name.mes) の `%4`（かぎかっこ 3 個目＝心の声） |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 属性 / かぎかっこ速記（同じ行き先） | 「かぎかっこと属性は別の意味」と言う | Medo 上はどちらも話者の `attrs` です |
| かぎかっこ速記 | 「ブラケット」だけを著者向けの本命にする | 文書の正称は **かぎかっこ速記**（コードでは `bracket` と呼ぶことがあります） |
| 姿勢（キー名） | 属性キー名に「ポーズ」 | 正は **姿勢**（英語エイリアス `pose` は可 → [ADR 0005](../decisions/0005-bracket-default-keys.md)） |
| プロファイル別の 2・3 個目 | 音声と漫画で同じ 2 個目だと思う | 音声の 2 個目は `声質`、漫画の 3 個目は `吹き出し`（[ADR 0007](../decisions/0007-profile-bracket-keys.md)） |

くわしい表は [デコレーター（かぎかっこ速記）](02-decorators.md#かぎかっこ速記任意) と [表情・姿勢・吹き出しの分け方](03-media-profiles.md#表情姿勢吹き出しの分け方--表情--姿勢--吹き出し) をどうぞ。  
属性がどこに付くかは [属性のつき先](02-decorators.md#属性のつき先) と下の節をどうぞ。

## 属性のつき先（まぎらわしいことば）

属性（`:key value`）は、ピースのなかの **直前のデコレーター** に付きます。  
ピース箱そのものに attrs はありません（Medo は `dialogue` と `decorators` だけです）。

| 使ってよい語 | 意味 | 注 |
|--------------|------|-----|
| **属性のつき先**＝直前のデコレーター | `@にか` の直後の `:表情 泣` は話者の `attrs` | [デコレーター](02-decorators.md#属性のつき先) |
| 直前が無い属性行 | ピース先頭やセリフのあとにだけ `:表情` がある | 参照パーサは **捨てずセリフ行に残す** |
| 表に無い行頭（`~` `※` など） | デコレーター表に無い記号 | kind `unknown` にはせず、セリフ行に残す |
| kind `unknown`（schema） | 手組み Medo などの逃げ道 | 参照パーサは通常出力しません |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 属性は直前のデコレーターへ | 「ピース直下の attrs」を v0 の本命にする | コアの古いイメージ文は廃止。schema にピース attrs はありません |
| 直前なしの `:key` はセリフに残す | 黙って消す／必ずエラーにする | 書き直しの手がかりを残します |
| 未知の行頭はセリフ | 未知の行頭を必ず kind `unknown` にする | schema の `unknown` は別用途です |
| 話者の属性は `@` へ | `%` や `^` に `:表情` などを付けるのを本命にする | 直前がコマ／構図だと、話者に届きません → [コマ・構図と属性](#コマ構図と属性まぎらわしいことば) |

## 原稿と二次出力（まぎらわしいことば）

上の三層の表を前提に、よくまざる言い方だけを並べます。

| 使ってよい語 | 層 | 意味 | 注 |
|--------------|----|------|-----|
| 原稿 | 1 | MesLang テキストそのもの | 人が書く入力。見本の `.mes` も原稿です |
| ネーム用途 / ネーム記述 | 1 | `profile: manga` でコマを書くときの用途の通称 | **原稿の一種**です。二次ツールの出力ではありません |
| 字コンテ用途 / 字コンテ下地 | 1 | `profile: anime` でカットを書くときの用途の通称 | **原稿の一種**です。完成した字コンテ表ではありません |
| Medo / 中間データ | 2 | 構造化 JSON | 原稿をパースした結果。カット表の材料です |
| 台本 / ネーム / 字コンテ（二次出力） | 3 | 整形・組版した読み物 | ツール側の成果です。原稿に見栄えは求めません |
| カット表 / 絵コンテ表（二次出力） | 3 | Medo から組み立てたカット行の並び | 原稿の外。仮形は [07-conte-table.md](07-conte-table.md)（[ADR 0008](../decisions/0008-conte-table-secondary.md)） |
| 参考画像 / 絵コンテ画像（二次成果物） | 3寄り | 見比べ用の画像など | Medo の欄にはしません。二次出力より広い「原稿の外」です |

文書で「ネーム例」と書くときは、**ネーム用途の原稿例** の意味です。完成ネームと混同しないようにします。  
「字コンテ下地」「字コンテ見本」も同じく、**字コンテ用途の原稿** を指します。カット表や絵コンテ画像と混ぜないでください。

## セリフのない間（音だけの間 / 無言コマ）

セリフがなくても、原稿のなかに「間」の一拍を置けます。  
聞こえるもの中心か、見えるコマ中心かで、呼び方だけそろえてください。どちらも **原稿の一部** です。

| 使ってよい語 | メディア | 意味 | 見本 |
|--------------|----------|------|------|
| **音だけの間** | 音声 | セリフのないピース。`$` / `!` / `&` / `#` などで音と状況だけを置く | [station.mes](../../examples/audio/station.mes) の「ランチへ」 |
| **無言コマ** / セリフなしコマ | 漫画 | セリフのない `%` コマ。`^` / `#` / `*` / `$` などで構図と状況だけを置く | [silent-panels.mes](../../examples/manga/silent-panels.mes)（`%7`＝目が合う、`%8`＝声を出す直前）、[station-two-pages.mes](../../examples/manga/station-two-pages.mes) の2ページ目 `%4` |

同じ信号待ちの拍を、音声では音だけの間、漫画では無言コマにした対比もあります（「ランチへ」↔ `station-two-pages` の `%4`）。  
文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 音だけの間（音声） | 音声のピースを「無言コマ」と呼ぶ | コマ（`%`）がないので、**間** と言います |
| 無言コマ / セリフなしコマ（漫画） | 漫画のコマを「音だけの間」と呼ぶ | 音メモ（`$`）があっても、画面の単位は **コマ** です |

「セリフなし」はどちらのメディアでも説明に使って構いません。呼び名を固定したいときは上表を優先してください。

## 見本の場面対応（まぎらわしいことば）

駅前の音声・漫画と、カフェ見本は **別の話** です。  
同じ「注文」ということばや、同じ `%10` という番号が出てきても、役割名は見本ごとに違います。迷ったら、まずこの早見で「いまどの見本の、どの拍か」を決めてから、下の各節へ進んでください。

| 役割名 | 音声 `station.mes` | 漫画 `station-name.mes` | ほかの見本 | くわしい呼び分け |
|--------|-------------------|------------------------|------------|------------------|
| **音だけの間** / **無言コマ** | 「ランチへ」 | — | [station-two-pages.mes](../../examples/manga/station-two-pages.mes) 2ページ目 `%4`（信号待ち）。[silent-panels.mes](../../examples/manga/silent-panels.mes) は会話前の無言 | [音だけの間 / 無言コマ](#セリフのない間音だけの間--無言コマ) |
| **到着の拍** | 「店の前」 | `%8`–`%9`（外注ぎ→入店） | — | [到着の拍](#到着の拍まぎらわしいことば) |
| **席について** | 「席について」 | `%10` | — | [到着の拍と店内](#到着の拍と店内まぎらわしいことば) |
| **注文を取る** | 「注文」 | `%11` | — | [店内の続きと注文](#店内の続きと注文まぎらわしいことば) |
| **任せたあと** | — | — | [cafe-pose.mes](../../examples/manga/cafe-pose.mes) `%10`（客どうしで決める） | [任せたあとと注文を取る](#任せたあとと注文を取るまぎらわしいことば) |
| **ふつうのセリフに戻る** | — | — | cafe-pose `%9`（心の声のあと） | [入店とふつうのセリフに戻る](#入店とふつうのセリフに戻るまぎらわしいことば) |

**店内の続き**（総称）は、駅前では「席について」＋「注文」（漫画 `%10`–`%11`）です。cafe-pose の `%10` は店内の続きではありません。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 見本の場面対応（早見） | 「`%10` はどの見本でも席について」と番号を予約語にする | 駅前 `%10`＝席について。cafe-pose `%10`＝任せたあと。番号は見本ごとの通しです |
| 駅前とカフェは別見本 | cafe-pose を駅前の続き／同じ「店内の続き」と呼ぶ | カフェ見本に入り口も店員もいません |
| 注文を取る（駅前）と任せたあと（カフェ） | 「注文」ということばだけで同一視する | 店員が取るのか、客どうしで決めるのかで振り分けます → [任せたあとと注文を取る](#任せたあとと注文を取るまぎらわしいことば) |

AI に渡すコピー用ひな形にも、同じ注意を短く入れてあります → [AI ガイド（基本指示・ネーム起こし）](04-ai-reading.md#読み手aiへの基本指示コピー用)。

到着から注文までの個別の表は、すぐ下の節から続きます。

## 到着の拍（まぎらわしいことば）

駅前の見本では、店の入り口に着くところを、音声と漫画で分けて書いています。  
物語の同じ区切りを指すときは **到着の拍** と言い、メディアごとの書き方の呼び名は下表にそろえます。

| 使ってよい語 | メディア | 意味 | 見本 |
|--------------|----------|------|------|
| **到着の拍** | 共通 | 店の入り口に着く、という物語の区切り全体 | 音声「店の前」↔ 漫画 `%8`–`%9` |
| **店の前**（セクション） | 音声 | 到着の拍をひとつの `==` にまとめた場面 | [station.mes](../../examples/audio/station.mes) の「店の前」 |
| **外注ぎ**（`%8`）→ **入店**（`%9`） | 漫画 | 到着の拍を2コマに分けた書き方。先にコマ外の声、次に戸を開けて入る | [station-name.mes](../../examples/manga/station-name.mes) の `%8` / `%9` |

音声の「店の前」は、入り口到着・ドアチャイム・セリフまでを **1セクション** に置きます。  
漫画では同じ到着を、**外注ぎ**（吹き出し種別）の `%8` と、ふつうのセリフで入る `%9`（入店）に分けます。`%9` だけが音声と一字一句同じ、という意味ではありません。  
到着の **あと**（戸が閉まり、席へ案内される店内）は別セクションです → [到着の拍と店内](#到着の拍と店内まぎらわしいことば)。

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 到着の拍（共通の区切り） | 音声の「店の前」だけを「外注ぎ」と呼ぶ | 外注ぎは漫画の **吹き出し種別** です（音声にコマ外の枠はありません） |
| 店の前（音声のセクション名） | 「店の前」＝漫画 `%8` だけ、と言い切る | 到着の拍全体は漫画では `%8`–`%9`。ドアチャイムと「逃げ場がない」は `%9` 側に寄ります |
| 外注ぎ / 入店（漫画のコマの役割） | `%8` や `%9` を「到着の拍」そのものの別名にする | 到着の拍は区切りの呼び名。コマの役割名とは別です |
| 入店（`%9`） | 入店を「音だけの間」「無言コマ」と呼ぶ | セリフがあります。セリフのない間とは別 → [音だけの間 / 無言コマ](#セリフのない間音だけの間--無言コマ) |
| 入店（駅前 `%9`） | cafe-pose の `%9` と同一視する | どちらも種別なしですが、役割名は別 → [入店とふつうのセリフに戻る](#入店とふつうのセリフに戻るまぎらわしいことば) |
| 到着の拍（入り口まで） | 「席について」までを到着の拍に含める | 席への案内は **店内の続き** です → [到着の拍と店内](#到着の拍と店内まぎらわしいことば) |

吹き出し種別の表は [メディアプロファイル（吹き出し）](03-media-profiles.md#吹き出しの書き方吹き出し-とかぎかっこ) をどうぞ。  
種別そのものの呼び分けは [吹き出し種別](#吹き出し種別心の声ナレ外注ぎ) をどうぞ。

## 到着の拍と店内（まぎらわしいことば）

駅前の音声見本では、入り口までの拍と、そのあとの店内を **セクションで分けて** います。  
店内も、席への案内と注文のように **複数のセクション** に分けて構いません。どちらも「店」の話ですが、物語の区切りは別です。

| 使ってよい語 | メディア | 意味 | 見本 |
|--------------|----------|------|------|
| **到着の拍** | 共通 | 入り口に着くまで（戸を開けて一歩入るところまで） | 音声「店の前」／漫画 `%8`–`%9` |
| **席について**（セクション／`%10`） | 音声／漫画 | 到着の **あと**。戸が閉まり、店内 BGM、席へ案内 | [station.mes](../../examples/audio/station.mes) の「席について」／ [station-name.mes](../../examples/manga/station-name.mes) の `%10` |
| **注文**（セクション／`%11`） | 音声／漫画 | 席についての **あと**。席の店員が注文を取る | [station.mes](../../examples/audio/station.mes) の「注文」／ [station-name.mes](../../examples/manga/station-name.mes) の `%11` |
| **店内の続き** | 共通（総称） | 到着の拍に含めない、店の中の場面 **全体**（複数セクション／複数コマでよい） | 音声「席について」＋「注文」／漫画 `%10`–`%11` |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 席について（音声のセクション名／漫画 `%10`） | 「席について」を「到着の拍」「入店」「注文」と呼ぶ | 入店は漫画 `%9` の役割名。席への案内は到着のあとの店内です。注文は次の拍です |
| 注文（音声のセクション名／漫画 `%11`） | 「注文」を「到着の拍」「席について」「任せたあと」と呼ぶ | 席に着いたあとの別拍です。cafe-pose `%10` の任せたあととは別見本です |
| 店内の続き（総称。漫画 `%10`–`%11`） | `%10` だけを「店内の続き」の別名にする | `$店内BGM` は店内側の語彙です。`%11`（注文）も店内です。総称の分け方は [店内の続きと注文](#店内の続きと注文まぎらわしいことば) |
| 到着の拍（入り口まで） | 漫画の `%10` や `%11` を「到着の拍」「入店」と呼ぶ | `%10` は席について、`%11` は注文。入店は `%9` |
| 席の店員（注文の `@店員`／漫画 `%11`） | 席に来る店員を「外注ぎ」と呼ぶ | 入り口 `%8` の外注ぎと話者名は同じでも、席での `%11` はふつうのセリフです → [吹き出し種別](#吹き出し種別心の声ナレ外注ぎ)／[店内の続きと注文](#店内の続きと注文まぎらわしいことば) |

到着の拍そのものの表は [到着の拍](#到着の拍まぎらわしいことば) をどうぞ。  
店内を複数の拍に分けるときの呼び分けは [店内の続きと注文](#店内の続きと注文まぎらわしいことば) をどうぞ。  
入店と種別リセットの呼び分けは [入店とふつうのセリフに戻る](#入店とふつうのセリフに戻るまぎらわしいことば) をどうぞ。

## 店内の続きと注文（まぎらわしいことば）

駅前の見本では、到着のあとの店内を **複数のセクション／コマ** に分けています。  
「店の中」というざっくりした呼び方と、席への案内・注文といった **拍の名前** は別です。迷ったら、総称なのか個別の拍なのかを先に言ってください。

| 使ってよい語 | メディア | 意味 | 見本 |
|--------------|----------|------|------|
| **店内の続き** | 共通（総称） | 到着の拍に含めない、店の中の場面全体。複数セクション／複数コマでよい | 音声「席について」＋「注文」／漫画 `%10`–`%11` |
| **席について** | 音声／漫画 `%10` | 店内の続きのうち、席へ案内する拍 | [station.mes](../../examples/audio/station.mes) の「席について」／ [station-name.mes](../../examples/manga/station-name.mes) の `%10` |
| **注文** | 音声／漫画 `%11` | 店内の続きのうち、席に店員が来て注文を取る拍 | [station.mes](../../examples/audio/station.mes) の「注文」／ [station-name.mes](../../examples/manga/station-name.mes) の `%11` |
| **席の店員** | 共通 | 注文の拍で席に来る `@店員`。ふつうのセリフ（種別なし） | 音声「注文」の `@店員`／漫画 `%11` |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 店内の続き（総称。複数可） | `%10` だけを「店内の続き」と呼ぶ | `%11`（注文）も店内の続きです。総称は `%10`–`%11` |
| 席について（`%10`） | `%10` を「注文」「入店」と呼ぶ | 席への案内です。到着の拍のあと |
| 注文（`%11`） | 「注文」を「席について」「到着の拍」「任せたあと」と呼ぶ | 席に着いたあとの別拍です。cafe-pose `%10` とは別見本です → [任せたあとと注文を取る](#任せたあとと注文を取るまぎらわしいことば) |
| 席の店員（`%11` の `@店員`） | 席に来る店員を「外注ぎ」と呼ぶ | 入り口 `%8` の外注ぎと話者名は同じでも、席ではふつうのセリフです → [吹き出し種別](#吹き出し種別心の声ナレ外注ぎ) |
| `%10`–`%11`（見本の通し） | 「店内の続き＝1コマ／1セクション」と決める | 音声は2セクション。漫画も2コマ。番号そのものは予約語ではありません |

入り口までの拍は [到着の拍](#到着の拍まぎらわしいことば) と [到着の拍と店内](#到着の拍と店内まぎらわしいことば) をどうぞ。  
入店と種別リセットの呼び分けは [入店とふつうのセリフに戻る](#入店とふつうのセリフに戻るまぎらわしいことば) をどうぞ。  
客どうしで決める「任せたあと」と、店員が取る「注文」の呼び分けは [任せたあとと注文を取る](#任せたあとと注文を取るまぎらわしいことば) をどうぞ。

## 任せたあとと注文を取る（まぎらわしいことば）

カフェ見本と駅前見本は、どちらも「注文」ということばが出てきます。  
迷ったら、「客どうしで何を頼むか決めたのか／席の店員が取りに来たのか」で振り分けてください。

| 使ってよい語 | 見本 | だれが話すか | 意味 |
|--------------|------|--------------|------|
| **任せたあと**（注文を決める） | [cafe-pose.mes](../../examples/manga/cafe-pose.mes) `%10` | 客どうし（`@こいと` `@にか`）。店員は出ない | メニューを閉じて、何を頼むかを決める。種別なしのまま続ける |
| **注文を取る**（駅前の **注文**） | 音声「注文」／ [station-name.mes](../../examples/manga/station-name.mes) `%11` | 席の店員が先、客が続く | 席に着いたあと、店員が注文を取る拍 |

共通点は「頼む内容が決まる」ことだけです。カフェ見本に店員は出てきません。駅前の注文は、席の `@店員` が「ご注文はお決まりですか」と取るところから始まります。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 任せたあと（cafe-pose `%10`） | cafe-pose の `%10` を「注文を取る」「席の店員」「店内の続き」と呼ぶ | 店員はいません。客どうしで決めています。駅前 `%10` は席について |
| 注文を取る（駅前 `%11`／音声「注文」） | 駅前の注文を「任せたあと」と呼ぶ | 店員が取りに来ます。cafe-pose とは別見本です → [店内の続きと注文](#店内の続きと注文まぎらわしいことば) |
| 注文を決める（任せたあとの説明） | 「注文を決める」＝駅前の「注文」セクションと思う | 決めるのは客側。取るのは店員側 |
| `%10` / `%11`（コマ番号） | 「`%10`＝任せたあと」「`%11`＝注文を取る」と番号を予約語にする | 番号は見本ごとの通しです。役割名は上表を優先 |

種別なしのまま続ける話は [入店とふつうのセリフに戻る](#入店とふつうのセリフに戻るまぎらわしいことば) をどうぞ。  
駅前の店内の総称と席の店員は [店内の続きと注文](#店内の続きと注文まぎらわしいことば) をどうぞ。  
見本どうしを横並びに見たいときは [見本の場面対応](#見本の場面対応まぎらわしいことば) をどうぞ。

## 入店とふつうのセリフに戻る（まぎらわしいことば）

駅前見本の `%9` とカフェ見本の `%9` は、どちらも **`:吹き出し` を付けない＝ふつうのセリフ** です。  
見た目は似ていても、見本での役割名は分けます。`%9` という番号そのものに特別な意味はありません（そのページの 9 コマ目、というだけです）。

| 使ってよい語 | 見本 | 直前のコマ | 意味 |
|--------------|------|------------|------|
| **入店** | [station-name.mes](../../examples/manga/station-name.mes) `%9` | 外注ぎ（`%8`） | [到着の拍](#到着の拍まぎらわしいことば)の後半。戸を開けて店に入る物語の役割 |
| **ふつうのセリフに戻る** | [cafe-pose.mes](../../examples/manga/cafe-pose.mes) `%9` | 心の声（`%8`） | 吹き出し種別を外して、口に出すセリフへ戻す |
| **任せたあと**（注文を決める） | [cafe-pose.mes](../../examples/manga/cafe-pose.mes) `%10` | ふつうのセリフに戻る（`%9`） | 種別なしのまま会話を続ける（同じコマに二人セリフ可）。店員が取る注文とは別 → [任せたあとと注文を取る](#任せたあとと注文を取るまぎらわしいことば) |

共通点は「種別を付けない」ことだけです。到着の拍の話をしているときは **入店**、心の声のあとの種別リセットの話をしているときは **ふつうのセリフに戻る** と言ってください。  
リセットの **あと** も、種別を付けなければふつうのセリフのまま続けられます（cafe-pose の `%10`）。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 入店（駅前 `%9`） | cafe-pose の `%9` を「入店」と呼ぶ | カフェ見本に店の入り口はありません。吹き出しを戻しているだけです |
| ふつうのセリフに戻る（cafe-pose `%9`） | 駅前の入店を「ふつうのセリフに戻る」だけと呼ぶ | 種別を外している点は同じでも、物語の役割名は **入店** です |
| 任せたあと（cafe-pose `%10`） | cafe-pose の `%10` を「店内の続き」「注文を取る」と呼ぶ | 駅前 `%10`（席について）／`%11`（注文を取る）／音声「注文」（[店内の続きと注文](#店内の続きと注文まぎらわしいことば)／[任せたあとと注文を取る](#任せたあとと注文を取るまぎらわしいことば)）とは別見本・別役割です |
| `%9` / `%10` / `%11`（コマ番号） | 「`%9`＝入店」「`%10`＝店内」「`%11`＝注文」と番号を予約語にする | 番号は見本ごとの通し番号です。役割名は上表を優先 |

吹き出し種別の表は [メディアプロファイル（吹き出し）](03-media-profiles.md#吹き出しの書き方吹き出し-とかぎかっこ) をどうぞ。  
種別そのものの呼び分けは [吹き出し種別](#吹き出し種別心の声ナレ外注ぎ) をどうぞ。

## 吹き出し種別（心の声・ナレ・外注ぎ）

漫画では「ふつうのセリフ吹き出し」以外の枠を、属性キー **吹き出し**（かぎかっこ 3 個目でも可）で示します。  
値の語彙は自由ですが、見本と文書では次の呼び名にそろえます。

| 使ってよい語 | 書き方の例 | 意味 | 見本 |
|--------------|------------|------|------|
| **ふつうのセリフ**（種別なし） | `:吹き出し` を付けない | 口に出すふつうの吹き出し | cafe-pose `%9`–`%10`／station-name `%9`（入店）・`%11`（席の店員。役割名は別 → [入店と…](#入店とふつうのセリフに戻るまぎらわしいことば) / [店内の続きと注文](#店内の続きと注文まぎらわしいことば)） |
| **心の声** | `:吹き出し 心の声` / `[心の声]` | もやもや吹き出しなど。話者の頭の中 | station-name `%4`／cafe-pose `%8` |
| **ナレ** | `:吹き出し ナレ` | 顔のないナレーション枠 | station-name `%7` |
| **外注ぎ** | `[外注ぎ]` / `:吹き出し 外注ぎ` | コマの外からの声（顔は描かない） | station-name `%8` |

いちばんまぎらわしいのは、**話者名**と**吹き出し種別**です。見本では `@ナレ :吹き出し ナレ` と並ぶことがありますが、左は「だれの行か」、右は「枠の種類」です。話者名を `@ナレ` にしなくても、`:吹き出し ナレ` だけでナレ枠になります。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 吹き出し種別（`心の声` / `ナレ` / `外注ぎ`） | 種別を話者名だけに書く（例: `@心の声` だけで心の声扱い） | 種別は **吹き出し** キーへ。話者は `@…` |
| `@ナレ`（話者名の一例） | 「`@ナレ`＝ナレ枠」と決めつける | 話者名は自由。枠にするのは `:吹き出し ナレ`（またはかぎかっこ 3 個目） |
| 心の声 | 心の声を「外注ぎ」と呼ぶ | 外注ぎは **コマの外**。心の声は話者の内面 |
| ナレ | ナレを「心の声」と呼ぶ | ナレは顔のない説明枠。誰かの内面ではない |
| 外注ぎ | 外注ぎを「ナレ」と呼ぶ | 外注ぎは特定の声（店員など）。ナレは状況説明向き |
| 外注ぎ（入り口 `%8`） | 席での `@店員` を「外注ぎ」と呼ぶ | 話者名は同じでも、コマ外の声と席に来る店員は別の拍（音声「注文」／漫画 `%11`） |
| 種別なし＝ふつうのセリフ | 「`:吹き出し ふつう`」のような予約値があると思う | 付けないことがふつう。リセットの呼び分けは [入店と…](#入店とふつうのセリフに戻るまぎらわしいことば) |

書き方の表は [メディアプロファイル（吹き出し）](03-media-profiles.md#吹き出しの書き方吹き出し-とかぎかっこ) をどうぞ。  
属性とかぎかっこのどちらで書くかは [かぎかっこ速記と属性](#かぎかっこ速記と属性まぎらわしいことば) をどうぞ。

## コマとカット（まぎらわしいことば）

`%` はどのメディアでも Medo 上の kind は **`frame`（画面の区切り）** です。  
変わるのは著者向けの呼び名だけです。漫画では **コマ**、アニメでは **カット** と呼びます。

| 使ってよい語 | メディア | 意味 | 見本 |
|--------------|----------|------|------|
| **コマ**（`%`） | 漫画 | ページの中の画面の区切り | [station-name.mes](../../examples/manga/station-name.mes)、[silent-panels.mes](../../examples/manga/silent-panels.mes) |
| **カット**（`%`） | アニメ | 字コンテ下地での画面の区切り | [station-conte.mes](../../examples/animation/station-conte.mes) |
| **ページ**（`==`） | 漫画 | 紙面の区切り（セクション） | [station-two-pages.mes](../../examples/manga/station-two-pages.mes) |
| **セクション**（`==`） | 共通 | `==` 見出しのまとまり全般（章・ページなど） | 音声の「ランチへ」などもセクションです |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| コマ（漫画の `%`） | 漫画の `%` をいつも「カット」と呼ぶ | アニメ用語とまざります。ネームでは **コマ** を優先 |
| カット（アニメの `%`） | アニメの `%` をいつも「コマ」と呼ぶ | 漫画用語とまざります。字コンテ下地では **カット** を優先 |
| ページ（漫画の `==`） | ページ区切りに `%` を使う | `%` はコマ／カット。紙が変わるときは `==` → [メディアプロファイル](03-media-profiles.md#ページとコマの分け方) |
| カット表（二次出力） | 原稿の `%` そのものを「カット表」と呼ぶ | `%` は原稿の区切り。表に直したものは層3 → [用語集（三層）](#三層原稿--medo--カット表) / [07-conte-table.md](07-conte-table.md) |

音声では絵がないので、`%` はふつう使いません。  
ページが変わると `%` は 1 から数え直してよい、という約束は漫画ネーム向けです（通し番号にしなくて大丈夫です）。

## コマとピース（まぎらわしいことば）

**コマ**（`%`）は画面の区切り、**ピース**は空行で区切るいちばん小さなまとまりです。  
ふつうは「1コマ＝1ピース」で足りますが、同じコマに吹き出しがふたつ以上あるときは、ピースのほうが細かくなります。

| 使ってよい語 | 意味 | 見本 |
|--------------|------|------|
| **コマ**（`%`） | ページの中の画面の区切り | `%6` がひとつあればコマはひとつ |
| **ピース**（空行区切り） | 発話やメモのいちばん小さな塊 | 同じ `%` のあとに空行で `@` を続けるとピースが増える |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 同じコマの複数ピース | 「1コマ＝1ピース」を絶対ルールにする | 目安です。同じコマの短いやりとりでは `%` は先頭だけ |
| `%` なしの続きピース | 続きのセリフにも毎回 `%` を振る | 新しいコマになってしまいます |
| コマ（画面） | ピースを「コマ」と呼ぶ | ピースは原稿の区切り。画面の単位は `%` |

見本: [station-name.mes](../../examples/manga/station-name.mes) の `%6`（二人の短いやりとり）。  
書き方は [メディアプロファイル（同じコマに複数のセリフ）](03-media-profiles.md#同じコマに複数のセリフコマとピース) をどうぞ。  
二次のカット表でも `%` なしピースは直前の区切りへ足します（[07-conte-table.md](07-conte-table.md)）。  
表情などを `%` や `^` に付けない話は [コマ・構図と属性](#コマ構図と属性まぎらわしいことば) をどうぞ。

## コマ・構図と属性（まぎらわしいことば）

ネームで迷いやすいのは、「コマ番号・構図」と「いまの話者の顔・体・吹き出し」の行き先です。  
機械は、属性を **直前のデコレーター** に付けます。`%` や `^` の直後に `:表情` を書くと、コマや構図のメモになり、話者には届きません。

| 使ってよい語 | 行き先 | 意味 | 見本 |
|--------------|--------|------|------|
| **コマ**（`%`） | 行頭記号の値 | コマ番号や短いメモ。話者属性は付けない | [station-name.mes](../../examples/manga/station-name.mes) の `%2` |
| **構図**（`^`） | 行頭記号の値 | 寄り・引き・大きさ（`1/2コマ` など）。話者属性は付けない | 同見本の `^にかバストアップ 1/2コマ`、[cafe-pose.mes](../../examples/manga/cafe-pose.mes) |
| **話者の属性** | `@` の直後（かぎかっこでも可） | `:表情` / `:姿勢` / `:吹き出し` | cafe-pose の `%2`（`:表情` `:姿勢`）、station-name の `%4`（かぎかっこ） |

大きさは `^` の本文へ続けて書いてください（`^にか寄り 1/3コマ`）。`%2 :大きさ 1/3` のような属性は、v0 の見本では使いません。

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 話者の属性は `@` へ | `%2 :表情 焦り` や `^寄り :姿勢 前傾` を本命にする | パーサは付けますが、顔と体は話者に届きません |
| 大きさは `^` の本文 | コマ番号 `%` に大きさ属性を足すのを本命にする | `^1/2コマ` で足ります |
| `%` / `^` はコマ先頭 | 続きピースのセリフに毎回 `^` を振るのを必須にする | `%` と同じく、構図も先頭ピースだけで足りることが多いです → [コマとピース](#コマとピースまぎらわしいことば) |

機械のつき先そのものは [属性のつき先](#属性のつき先まぎらわしいことば) です。書き方の失敗例は [メディアプロファイル](03-media-profiles.md#コマ構図に属性を付けない) をどうぞ。

## タイミングとビート（まぎらわしいことば）

「間」や「長さ」を書く記号がふたつあります。  
迷ったら、「時計で測りたい長さか／感じとしての間か」で振り分けてください。

| 使ってよい語 | 記号 / kind | 意味 | 見本 |
|--------------|-------------|------|------|
| **タイミング** / 尺 | `&` / `timing` | 秒数・字幕時刻・尺の目安 | [station.mes](../../examples/audio/station.mes) の `&0:08` / `&約1.5秒`、取り込み三段階の `&少し間を置いて`、[station-conte.mes](../../examples/animation/station-conte.mes) の `&4s` |
| **ビート** / 間のメモ | `*` / `beat` | テンポや間の感じ（測らなくてよい） | [silent-panels.mes](../../examples/manga/silent-panels.mes) の `*間`、[station-two-pages.mes](../../examples/manga/station-two-pages.mes) の `%4` の `*間` |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| タイミング / 尺（`&`） | `&` をいつも「ビート」と呼ぶ | 字幕やカット尺など、**長さの目安**が本命です |
| ビート / 間のメモ（`*`） | `*` にタイムコードを書くのを本命にする | 漫画の「ちょっと間」など、**感じ**のメモ向きです |
| ことばの間メモ（`&少し間を置いて`） | 音声の柔らかい間を無理に `*` へ直す | 音声見本どおり、ことばメモは `&` のままで構いません。旧 Mes 取り込みでも `&` のまま残します |

どちらも必須ではありません。なくて大丈夫です。  
音声・アニメでは `&` をよく使い、漫画の無言コマでは `*` がよく出ます。同じ「間」でも、記号はメディアの慣習に合わせて選んでください。  
旧音声原稿の取り込み見本は三段階です（[before](../../examples/audio/mes-import-before.mes) → [compat-only](../../examples/audio/mes-import-compat-only.mes) → [after](../../examples/audio/mes-import-after.mes)）。間はどの段階でも `&` 側だけで、`*` は混ぜていません。

## 音・声質・ヘッダー変数（まぎらわしいことば）

`$` は場所と書き方で意味が分かれます。  
迷ったら「ヘッダーか本文か」「聞こえる出来事か／いまの話者の声か／演技か」で振り分けてください。

| 使ってよい語 | どこ | 意味 | 例 |
|--------------|------|------|----|
| **ヘッダー変数**（`$key value`） | ヘッダー（`----` の前） | 作品のメタ情報。`key: value` と同じ | `$title 駅前の二人` |
| **音** / 音響（本文の `$` / kind `sound`） | ボディ | 聞こえる出来事（環境音・効果音・BGM・場の声など） | `$雑踏` `$発車ベル` |
| **声質**（`:声質` / かぎかっこ 2 個目） | 話者（`@`）の属性 | いまの話者の声の出し方 | `@にか :声質 ヒソヒソ` |
| **ト書き**（`#`） | ボディ | 動き・顔・気持ちの演技や状況 | `#少し呆れた感じ` |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| ヘッダー変数 / `$title` など | ヘッダーの `$` を「音」と呼ぶ | `----` より前の `$` は音ではありません → [コア仕様](01-core.md#ヘッダーの--と本文の--は別もの) |
| 音 / 音響（本文の `$`） | 話者のささやきなどをいつも `$` と呼ぶ | 場の声・他人の声は `$`。**いまの話者**の出し方は `:声質` が本命です |
| 声質（`:声質`） | 声質をト書きだけに書く | `#ヒソヒソ` でも読めますが、話者に紐づけたいときは属性へ |
| ト書き（`#`） | `#` を音のメモと呼ぶ | 聞こえるものは `$`、演技の中身は `#` |

旧 Mes の `$ヒソヒソ声` は、**本文の `$` のまま残しても誤りではありません**。  
話者に紐づけたいときだけ `:声質` へ移します（[取り込みガイド](06-mes-compat.md) / [音声プロファイルの分け方](03-media-profiles.md#音声質ト書きの分け方)）。

見本: [station.mes](../../examples/audio/station.mes) の「改札を出て」（`$` / `!` / `&` と `:声質` の共存）、取り込みの三段階（[before](../../examples/audio/mes-import-before.mes) → [compat-only](../../examples/audio/mes-import-compat-only.mes) → [after](../../examples/audio/mes-import-after.mes)。compat-only では `$ヒソヒソ声` がまだ `$`）。

## 音の位置と話者の位置（まぎらわしいことば）

`!` は **位置のメモ** です。同じ記号で、次のどちらにも使えます。

| 使ってよい語 | いつ | 意味 | 例 |
|--------------|------|------|----|
| **音の位置** | `$` の近く | その音がどこから聞こえるか | `$発車ベル` の次に `!遠方` |
| **話者の位置** | `@` のピースで、`$` がなくてもよい | いま話している人がどこにいるか | `@こいと` のピースに `!左寄り` だけ |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 音の位置 / 話者の位置（どちらも `!`） | `$` がない `!` を「足りない」「誤り」と呼ぶ | `$` なしの `!` は話者の位置メモとして正しいです |
| 位置メモ（`!`） | `!` をいつも「効果音のパン」だけと呼ぶ | 人の立ち位置にも使います |
| 音と位置を隣の行に | 「この `$` はこの `!`」をコアの硬い紐づけにする | v0 では出てきた順の目安まで（[語彙ガイド](03-media-profiles.md#音と位置の語彙ガイドよく使う書き方)） |

旧 Mes でも `!` はそのまま読めます。取り込みで直す必要はありません（[06-mes-compat.md](06-mes-compat.md)）。  
見本: [station.mes](../../examples/audio/station.mes) の `@にか[思索][ヒソヒソ]` ピース（`!正面やや右` だけで `$` なし）、取り込み後の [mes-import-after.mes](../../examples/audio/mes-import-after.mes) の `@こいと` ピース（`!正面` だけ）。

## `#` まわり（まぎらわしいことば）

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| ト書き（`#` / kind `comment`） | 「コメント」だけと言う | コード上の kind は歴史的に `comment`。著者向け文書では **ト書き** を優先します |
| コメントアウト（行頭 `//`） | `#` をコメントアウトと呼ぶ | 行頭の `//` だけ読み飛ばします。途中の `//` は残ります。閉じかぎのうしろだと糖衣しません → [下の節](#コメントアウト行頭だけまぎらわしいことば) |
| 柱書き | `#` を章見出しの本命と呼ぶ | 旧 Mes のことば。MesLang の本命は **セクション（`==`）** です → [ADR 0003](../decisions/0003-hash-is-comment-not-section.md) |

## コメントアウト（行頭だけ）（まぎらわしいことば）

`//` はト書き（`#`）ではなく、**読み飛ばす行**です。  
MesLang が削るのは **行頭**の `//` だけです。旧 Mes の `DoFlat_DeleteCommentout` は、行の途中の `//` 以降も消していました。

| 書き方 | MesLang | 旧 Mes |
|--------|---------|--------|
| 行頭 `//メモ` | その行を読み飛ばす | 同じ（行が消える） |
| 途中 `セリフ //メモ` | **セリフに残る** | `//` 以降を削る |
| `$雑踏 //大きめ` | 音の値に残る | `//` 以降を削る |
| 前に空白がある `  //メモ` | コメントアウトにならない | `//` 以降を削る |
| `名前「セリフ」 //メモ`（閉じかぎのあと） | **糖衣がかからない**。行全体がセリフに残る | 先に `//` 以降を消してから糖衣する |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| コメントアウト（行頭 `//`） | `#` をコメントアウトと呼ぶ | ト書きは `#`。読み飛ばしは `//` |
| 行頭だけ削る | 途中の `//` も `--compat` が消すと思う | 互換レイヤは触りません。消したいときは人が行頭へ寄せます |
| 途中の `//` は原文の一部 | 旧 Mes と同じく途中も消えると思う | セリフや `$` の値に残ります |
| 途中の `//` はかぎかっこ内か `$` 行へ | 閉じかぎのうしろに `//` を置く | `名前「セリフ」` 糖衣は、行末が `」` のときだけです |

取り込みで直す必要はありません。見本の三段階には、機械が触らない行頭 `//` と、かぎかっこ内／`$` 行の途中の `//` を置いてあります（[mes-import-before.mes](../../examples/audio/mes-import-before.mes) ほか）。  
閉じかぎのうしろへ `//` を移したいときは、人がかぎかっこの中へ入れるか、行頭へ寄せてください。  
手順は [取り込みガイド](06-mes-compat.md#コメントアウトは行頭だけ)、コアの約束は [01-core.md](01-core.md) をどうぞ。

## 取り込みの三段階（機械変換と人手）

旧 Mes から移すときは、**機械が直すこと**と **人が決めること** を分けます。  
見本も三段階に揃えてあります。迷ったら「いまどの段階か」を先に言ってください。

| 段階 | 見本 | だれが直すか | 中身の目安 |
|------|------|--------------|------------|
| **1. 取り込み前** | [mes-import-before.mes](../../examples/audio/mes-import-before.mes) | （まだ直していない） | 行頭 `○` / `◯`、章らしい `#`、旧流儀の `$ヒソヒソ声`、行頭 `//`、途中の `//`（かぎかっこ内と `$`）、全角空白のセリフ行 |
| **2. 機械変換だけ** | [mes-import-compat-only.mes](../../examples/audio/mes-import-compat-only.mes) | **機械**（`rewriteMesCompat` / `--compat`） | 柱だけ `#`。章も声質もまだ人手前 |
| **3. 人手のあと** | [mes-import-after.mes](../../examples/audio/mes-import-after.mes) | **人**（任意） | `==` 化、`:声質` 移動など。場の `$` / `!` と `&` はそのまま |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| **機械変換** / 互換レイヤ | `--compat` で章や声質まで全部直ると思う | 機械が触るのは行頭の `○` / `◯` → `#` だけです |
| **人手** / 人の判断 | 機械変換直後を「完成した MesLang」と呼ぶ | `#オープニング`→`==`、`$ヒソヒソ声`→`:声質` は任意の人手です |
| ヘッダーに `profile` がなくてもよい | 取り込み前を「profile 欠け＝誤り」とする | **ヘッダーの縁**。機械は補わない。人手のあとで `profile: audio` を足してよい（after 見本） |
| 三段階の見本 | before / after だけで compat-only を飛ばす | 機械のあとと人手のあとを見比べると境界が分かります |
| 似た形の `〇`（U+3007） | `〇` も柱として機械が直すと思う | 柱ではないので触りません → [よくあるつまずき](06-mes-compat.md#よくあるつまずき----と-〇) |
| 全角空白のセリフ行 | `--compat` や DoFlat が `@` に直すと思う | 糖衣しない。半角4つ／タブだけ → [速記の空白](#速記の空白半角と全角まぎらわしいことば) |

手順の本編は [取り込みガイド](06-mes-compat.md)、決定理由は [ADR 0006](../decisions/0006-mes-compat-import.md) をどうぞ。  
`$` と `:声質` の棚は [音・声質・ヘッダー変数](#音声質ヘッダー変数まぎらわしいことば)、`#` と `==` は [上の節](#-まわりまぎらわしいことば) もあわせてどうぞ。  
`profile` なしは [ヘッダーの縁](#medo-の形チェックの縁まぎらわしいことば) です。

## 記号の呼び名

| 記号 | kind（Medo） | やさしい言い方 | 著者向けの呼び名 |
|------|--------------|----------------|------------------|
| `@` | character | だれが話しているか | 発言者 / 主体 |
| `#` | comment | ト書き・状況・演技 | ト書き・状況 |
| `$` | sound | 音のこと | 音響 |
| `!` | position | 音や人の位置 | 位置 / 空間 |
| `&` | timing | タイミング | タイミング / 尺 → [呼び分け](#タイミングとビートまぎらわしいことば) |
| `?` | ext | まだ名前のないメモ | 拡張（ツール固有） |
| `%` | frame | 画面の区切り | コマ / カット（プロファイル）→ [呼び分け](#コマとカットまぎらわしいことば) |
| `^` | camera | どう見せるか | 構図 / カメラ指示（プロファイル）→ 漫画は [構図の語彙](03-media-profiles.md#構図の語彙ガイドよく使う書き方)、アニメは [カメラの語彙](03-media-profiles.md#カメラと尺の語彙ガイドよく使う書き方) |
| `*` | beat | 間やテンポ | ビート（任意）→ [呼び分け](#タイミングとビートまぎらわしいことば) |

仕様表の英語列は **kind** と書きます。著者向けの説明では日本語の呼び名を使います。  
メディアごとの言い方のちがいは [メディアプロファイルの表](03-media-profiles.md#記号の意味はどのメディアでもだいたい同じです) をどうぞ。  
全角と半角の対応は下の [呼び分け](#全角半角の行頭記号まぎらわしいことば) をどうぞ。

## 全角／半角の行頭記号（まぎらわしいことば）

行頭の記号は、全角でも半角でも **同じ意味** です。  
ツールも AI も、見た目の幅では区別しません（Medo の kind は同じ。入力の形は `rawMark` に残ります）。

| 使ってよい語 | 意味 | 注 |
|--------------|------|-----|
| **半角の行頭記号**（`@` `#` `%` など） | 見本や新規原稿でおすすめの形 | 半角に揃えると読みやすいです |
| **全角の行頭記号**（`＠` `＃` `％` など） | 半角と **同じ kind** | 既存原稿にあっても誤りではありません |

よく出る対応は次のとおりです。

| 半角 | 全角 | kind（Medo） | やさしい言い方 |
|------|------|--------------|----------------|
| `@` | `＠` | character | だれが話しているか |
| `#` | `＃` | comment | ト書き・状況 |
| `$` | `＄` | sound | 音のこと |
| `!` | `！` | position | 位置 / 空間 |
| `&` | `＆` | timing | タイミング / 尺 |
| `?` | `？` | ext | 拡張メモ |
| `%` | `％` | frame | コマ / カット |
| `^` | `＾` | camera | 構図 / カメラ |
| `*` | `＊` | beat | ビート |

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 全角も半角も同じ行頭記号 | 全角だけ「未知の記号」と呼ぶ | `％`＝コマ/カット、`＾`＝構図/カメラ、`＊`＝ビートです |
| 新規は半角推奨 | 既存の全角を「誤り」として直す | 半角化は任意の「提案:」までにします |
| `rawMark` はそのまま | パース結果で全角を半角に直すのを必須にする | Medo の `rawMark` は入力どおり残します |

くわしくは [コア仕様](01-core.md)・[デコレーター表](02-decorators.md)・[AI ガイド](04-ai-reading.md) をどうぞ。

行頭記号は全角でも半角でも同じ意味ですが、**空白は別**です。話者速記の空白は半角だけです → [下の節](#速記の空白半角と全角まぎらわしいことば)。

## 速記の空白（半角と全角）（まぎらわしいことば）

`名前` のあとに空白を置いてセリフを書く速記は、**半角のスペース4つ**か **タブ**だけです。  
日本語入力の **全角空白**（見た目は広いスペース）では糖衣しません。行頭記号の全角／半角とは別の話です。

| 書き方 | パース後 | 注 |
|--------|----------|-----|
| `名前` + **半角スペース4つ** + セリフ | `@名前` + セリフ | コアの DoFlat。`--compat` は触らない |
| `名前` + **タブ** + セリフ | 同上 | 見た目が分かりにくいので、見本は全角空白側を実例にしています |
| `名前「セリフ」` | 同上 | かぎかっこの速記。空白とは別形 |
| `名前` + **全角空白**（いくつでも）+ セリフ | **セリフ行のまま** | 話者にならない。半角4つへ直すか、`「」` / `@` で書く |

見本の三段階には、全角空白4つの行を置いてあります（[mes-import-before.mes](../../examples/audio/mes-import-before.mes) ほか）。機械変換のあとも同じ文面です。人手のあとでも `@` には直していません（糖衣しない実例のまま）。

文書では次のように呼び分けます。

| 使ってよい語 | 使わない／避ける語 | 注 |
|--------------|-------------------|-----|
| 半角スペース4つ／タブは速記 | 全角空白4つも話者速記だと思う | 全角空白は IME で入りやすいですが、v0 では糖衣しません |
| 全角空白では糖衣しない | 行頭記号の全角と同じく空白も全角でよいと思う | 行頭の `@`／`＠` は同じ kind。空白は半角だけです → [全角／半角の行頭記号](#全角半角の行頭記号まぎらわしいことば) |
| `--compat` は触らない | 取り込みの機械変換が空白を `@` に直すと思う | 柱（`○`／`◯`）だけです。速記はパース時の DoFlat |
| 形の誤りではない | 全角空白の行を「壊れた原稿」と呼ぶ | セリフとして残ります。直したいときは半角4つ／タブ／`「」`／`@` へ（任意の「提案:」） |

コアの表は [01-core.md](01-core.md#速記の橋渡しdoflat)、取り込みの境目は [取り込みの三段階](#取り込みの三段階機械変換と人手) と [取り込みガイド](06-mes-compat.md#速記の空白は半角だけ全角では糖衣しない) をどうぞ。

## 採用しない／コアに入れない案

迷ったときに戻れるよう、見送った案をここにまとめます。くわしい理由は各 ADR や概要をどうぞ。  
日次バックログの **wont（v0）** と同じ一覧です。どちらか一方だけに足さないでください。

| 案 | 扱い | 根拠 |
|----|------|------|
| `::img=` のような HTML 風属性 | **採用しない** | [ADR 0002](../decisions/0002-attribute-syntax.md)。正本は `:key value`。アイコンは `:img …` で足りる |
| 属性キー名としての「ポーズ」 | **使わない** | [ADR 0005](../decisions/0005-bracket-default-keys.md)。正は **姿勢**（英語エイリアス `pose` は可） |
| コアの `#第一章` → `==` 自動昇格 | **コアではしない** | [ADR 0003](../decisions/0003-hash-is-comment-not-section.md)。互換取り込み側の任意処理 |
| 旧 Mes の `○` / `◯` 柱 | **コア外** | 取り込み時に `#` へ（[ADR 0006](../decisions/0006-mes-compat-import.md) / [ガイド](06-mes-compat.md)）。コア DoFlat には入れない。似た形の `〇`（U+3007）は柱ではないので公式互換でも直さない |
| `（ト書き）` / `【ト書き】` 行の自動変換 | **コア／公式互換には入れない** | [ADR 0006](../decisions/0006-mes-compat-import.md)。旧 Mes のツール固有のまま |
| 原稿への画像埋め込み（必須欄） | **しない** | [ADR 0004](../decisions/0004-manga-reference-images.md)。参考画像は二次成果物 |
| ゲーム（VN）の選択肢・分岐 DSL | **コアに入れない** | [概要](00-overview.md) / ロードマップ M4。必要なら別プロファイル |
| 厳密な音響座標系 | **いまは決めない** | 音声プロファイルは左右・遠近のメモまで |
| 専用 GUI エディタ必須 | **やらない** | 哲学・概要。テキストだけで書けることを優先 |
| カット表の Markdown／CSV 整形をコアへ | **コアには入れない** | [ADR 0008](../decisions/0008-conte-table-secondary.md)。二次ツール側の候補 |
| 途中の `//` を互換レイヤで削ること | **コア／公式互換には入れない** | [ADR 0006](../decisions/0006-mes-compat-import.md)。MesLang は行頭だけ。旧 Mes の `DeleteCommentout` は `//.*` |
| 全角空白4つを半角空白4つと同じ速記にすること | **コアではしない** | DoFlat の空白速記は半角スペース4つ／タブだけ。全角空白はセリフのまま（[速記の空白](#速記の空白半角と全角まぎらわしいことば)） |

ADR の目次は [docs/decisions/](../decisions/README.md) にあります。
