# AI が MesLang を読むための約束

MesLang は、ツールだけでなく、ネーム生成・字コンテ起こし・台本整形などを行う AI の入力にも使います。

層の呼び方は **原稿 → Medo → カット表などの二次出力** です（[用語集](05-glossary.md#三層原稿--medo--カット表)）。AI が整える読み物は層3で、原稿そのものに見栄えを足さないでください。

## 読み手（AI）への基本指示（コピー用）

```
あなたは MesLang 原稿を読む。
- 空行区切りの「ピース」が時間 / コマ / 発話の単位
- 行頭記号: @話者 #ト書き $音 !位置 &タイミング %コマ/カット ^カメラ *ビート
- 全角の行頭記号（＠＃＄！＆？％＾＊）は半角と同じ意味。読み取りでは区別しない（％＝コマ/カット、＾＝構図/カメラ、＊＝ビート）
- & は秒数・字幕・尺の目安。* は感じとしての間メモ。音声の「&少し間を置いて」は & のままでよい（無理に * へ直さない）
- 文書の章・ページ区切りは == セクション。#第一章 のような行もト書きであり章見出しではない
- ヘッダー（---- より前）の $key value はメタ変数。ボディの $ は音。混同しない
- :key value は属性。特に :表情 はキャラIDを変えずに表情を表す
- @名前[…] のかぎかっこ速記は profile で行き先が変わる（audio: 2個目=声質 / manga: 3個目=吹き出し）。ヘッダー bracket-keys で上書き可
- 記号は構造、# と属性値の自然言語はニュアンス
- // 行はコメントアウト（無視）。# と混同しない
- 書いていない情報は推測で断定せず、不足として列挙する
```

全角と半角の約束は [用語集](05-glossary.md#全角半角の行頭記号まぎらわしいことば)・[コア仕様](01-core.md)・[デコレーター表](02-decorators.md) にもあります。  
「デコレーター」と「行頭記号」は同じ仲間です（[用語集](05-glossary.md#デコレーターと行頭記号まぎらわしいことば)）。属性（`:key value`）は行頭記号ではなく、記号行に付くものです。

## 著者側の書き方（AI に渡すとき）

1. **構造は記号で** — だれが話すか、何コマ目かは `@` `%` で明示しましょう
2. **ニュアンスはことばで** — 「なんか悲しい感じ」より「口元は笑っているが目が合わない」
3. **曖昧さを残すなら、意図して** — `#（表情は絵師に委ねる）` のように書くと伝わります
4. **プロファイルを明示** — ヘッダーに `profile: manga` などと書き、出力の期待を固定しましょう

## AI に MesLang を書かせるとき

- まずピース分割を守らせます（1 発話 / 1 コマ / 1 カットの意図ごとに空行）
- 飾りを盛りすぎないようにします（必須はセリフと、そのメディアでどうしても要るもの）
- 知らない記号を発明させないようにします。足りなければ `#` か `?` か属性キーを使います
- 行頭記号は **半角**（`@` `#` `%` など）で書くのが無難です。全角でも意味は同じですが、見本に合わせて半角に揃えます
- 既存原稿の全角記号を「誤り」として直さないでください（半角化は任意の「提案:」まで）
- 音声・漫画・アニメそれぞれに「原稿を書かせる」ひな形があります（下へ）
- アニメなら `%`（カット）・`^`（カメラ）・`&`（尺）を先に置き、ツール固有の ID は `?` へ逃がします

## おすすめの実務の順番

AI に渡す前に、形だけはツールへ任せると安心です。

1. **形チェック（ツール）** — Medo は `--validate` / `npm run validate`。カット表なら `--conte --validate`。箱の名前と型だけを見ます（[用語集](05-glossary.md#形チェックと目視まぎらわしいことば)）
2. **不足の洗い出し（AI）** — 下の「不足情報の洗い出し」ひな形。原文は書き換えさせない
3. **起こし・台本化・生成（AI）** — ネーム起こし、台本化、原稿生成など。足りないところは「提案:」で分ける
4. **数字の集計（ツール）** — セリフ文字数は `--count` / `npm run count` が本命（下のひな形）

旧 Mes からの取り込みなら、先に `--compat`（必要なら `--compat --validate`）を通してから 2 へ進みます。

## ツールと AI の役割分担

| 役割 | ツール（パーサ） | AI |
|------|------------------|-----|
| ピース分割・記号の割り当て | はっきり決める | 手伝いはよいが、最終はツール |
| 表情とキャラ名の分離 | 属性として保持 | 集計やアイコン割り当てに利用 |
| 絵の構図の具体化 | しない | `#` `^` `%` から提案 |
| カット表（conte-table）への整形 | `toConteTable` が本命 | 人向け表の補助。機械形はツール優先 |
| 足りない情報の洗い出し | しない | 「不足:」「提案:」に分けて列挙（下のひな形） |
| 足りない情報の補完 | しない | 提案として出し、原文は残す |
| セリフ文字数の集計 | `--count` が本命 | 概算や目標字数との照合は手伝ってよい |

## プロンプトのひな形

### 漫画ネーム起こし

```
次の MesLang（profile: manga）を、ページごとのネーム概要にして。
- == はページ区切り、% はそのページ内のコマ。混同しない（漫画では % を「カット」と呼ばない）
- ページが変わると % は 1 から数え直すことがある。番号だけで全話を通した通し番号だと思わない
- 出力は == ごとに見出しを分け、その下にコマを並べる
- 各コマについて: 構図（^） / 状況（#） / キャラ配置 / 表情 / 姿勢 / 吹き出し種別 / セリフ を短く
- ^ は寄り・引き・俯瞰・目線の高さ・1/2コマなど「どう見せるか」（カメラと呼ばない。漫画では構図）。無言コマほど ^ を丁寧に読む
- :表情 とかぎかっこ 1 個目、:姿勢 とかぎかっこ 2 個目は同じ行き先（話者に紐づく）
- セリフが無いコマ（dialogue 空）もコマとして扱い、「無言」「間」と明記する。勝手にセリフを足さない
- :吹き出し とかぎかっこ 3 個目は同じ意味（心の声など）。あれば概要でも「心の声」など種別を明記し、ふつうのセリフ吹き出しと混ぜない
- 原文にない設定は「提案:」と印をつけて分けて書く
```

入力例（セリフなしページ）: [examples/manga/silent-panels.mes](../../examples/manga/silent-panels.mes)（`%7`＝目が合う無言。`%8`＝声を出す直前。どちらもセリフなし）  
入力例（会話あり・1ページ）: [examples/manga/station-name.mes](../../examples/manga/station-name.mes)（かぎかっこ 3 個目の心の声）  
入力例（2ページ通し・`%` 数え直し）: [examples/manga/station-two-pages.mes](../../examples/manga/station-two-pages.mes)  
入力例（表情・姿勢・`:吹き出し`）: [examples/manga/cafe-pose.mes](../../examples/manga/cafe-pose.mes)（`%8`＝属性の心の声。`%9`＝そのあとふつうのセリフに戻る）  
呼び分け: [用語集（コマとカット）](05-glossary.md#コマとカットまぎらわしいことば)  
構図の言い方: [メディアプロファイル（構図の語彙）](03-media-profiles.md#構図の語彙ガイドよく使う書き方)

### 漫画参考画像（サンプル提示・ネーム確認）

```
次の MesLang（profile: manga）を、== セクション（ページ）ごとに白黒漫画ネーム風の1枚絵として生成する。
1ページ（== 1つ）＝1画像。複数ページなら枚数を合わせる。コマ割り・吹き出し・表情は % ^ # @ とセリフから読み取る。
コマの読み順は日本の漫画どおり右→左、上→下（横並びなら右コマが先）。吹き出し内は縦書き。
^ に書かれた 寄り・引き・俯瞰・目線の高さ・1/2コマ・2/3コマ などの構図メモはコマ割りに反映する。
:吹き出し 心の声（またはかぎかっこ 3 個目）があるセリフは、ふつうの吹き出しと形を分ける（もやもや吹き出しなど）。
セリフのないコマは吹き出しを描かず、# と ^ の内容だけで絵にする。勝手にセリフを足さない。
画像は原稿に埋め込まず、サンプルテキストの直下に参考として置く（人がテキストと見比べる用）。
```

### 音声台本化

```
次の MesLang（profile: audio）を、話者名付き台本形式に整形して。
$ と ! は音響メモ欄へ（環境音・効果音・BGM・場の声）。同じピース内で複数あるときは出てきた順で近いもの同士を組む目安にする（硬い紐づけはしない）。
$ のない ! だけは、話者の位置メモとして扱う（足りない音として補完しない）。
& はタイミング欄へ（あれば）。* があればビート／間メモ欄へ（秒数へ昇格しない）。
いまの話者の声の出し方（:声質 / かぎかっこ 2 個目）は演技メモ欄へ。旧原稿の $ヒソヒソ声 のような行が残っていても音響メモとして扱い、話者に紐づくと判断できるときだけ声質欄へ移す提案をしてよい。
ヘッダーの $title などはメタ情報であり、音響メモに混ぜない。
# はト書き欄へ。セリフ本文は装飾記号を付けない。
```

呼び分け: [用語集（音・声質・ヘッダー変数）](05-glossary.md#音声質ヘッダー変数まぎらわしいことば) / [用語集（音の位置と話者の位置）](05-glossary.md#音の位置と話者の位置まぎらわしいことば) / [用語集（タイミングとビート）](05-glossary.md#タイミングとビートまぎらわしいことば)

### セリフ文字数の照合（音声）

機械で集計するときは、参照パーサの `--count` / `npm run count` が本命です。  
AI に目標字数との照合や、話者ごとの偏りを見てもらうときは、次をコピーしてください。

```
次の MesLang（profile: audio）について、セリフ文字数を話者ごとにまとめて。
- 数えるのはセリフ本文だけ。@ / # / $ / ! / & / 属性 / かぎかっこは数えない
- 正確な集計はツール（--count）が本命。AI の数字は概算とし、ツール結果があればそちらを優先する
- 目標字数や上限が指示にあれば、「不足:」「超過:」で分ける。原文は書き換えない
- 削る・足す案は「提案:」に分け、勝手に原稿へ反映しない
```

見本: [examples/audio/station.mes](../../examples/audio/station.mes)

### 音声原稿を書かせるとき

```
次のあらすじを、MesLang（profile: audio）の音声脚本下地にして。
- 1発話＝1ピース（空行区切り）。セリフの前に @話者
- 聞こえる音は $、位置のメモは !、演技・状況は #。話者の声の出し方は :声質（またはかぎかっこ 2 個目）へ
- ! は音の位置にも話者の位置にも使える。$ なしの ! だけで話者の立ち位置を書いてよい
- 場の声・環境音・BGM を $ に書き、話者の声質と混ぜない
- セリフのない「音だけの間」も書いてよい（$ / ! / & / # だけ）。漫画の無言コマとは呼び分ける
- 尺・字幕の目安は &。感じとしての間だけなら * でもよいが、音声では &少し間を置いて のままでよい
- 飾りを盛りすぎない。必須はセリフ。音や位置は必要なところだけ
- ヘッダーに profile: audio と短い title を書く（$title でも可だが、本文の $音 と混ぜない）
- 知らない記号を発明しない。足りなければ # か ? か属性キーを使う
```

### 漫画ネーム原稿を書かせるとき

```
次のあらすじを、MesLang（profile: manga）のネーム原稿にして。
- == でページ、% でそのページ内のコマ。1コマ＝1ピース（空行区切り）。漫画では % を「カット」と呼ばない
```

### 不足情報の洗い出し（原稿チェック）

```
次の MesLang 原稿を読み、足りない情報だけを列挙して。
- 書いてある記号とことばは尊重する。原文を書き直さない
- 「断定して補完」はしない。不足は「不足:」で、足すなら案は「提案:」で分ける
- プロファイルごとに特に見る点:
  - audio: 話者（@）の抜け、場の音（$）と声質（:声質）の混同、音だけの間で音（$）や状況（#）が空な箇所。$ のない ! は話者の位置として正しいので不足にしない
  - manga: ==（ページ）と %（コマ）の抜け、ページをまたいだ % の通し番号化の疑い、無言コマで構図（^）や状況（#）が空な箇所、表情と姿勢の行き先、心の声なのに :吹き出し（またはかぎかっこ 3 個目）が無い箇所
  - anime: %（カット）・カメラ（^）・尺（&）の抜け、? を ^/# へ昇格していないか
- 全角の行頭記号（％／＾／＊ など）を「未知の記号」や不足として挙げない（半角と同じ意味）
- ヘッダーの $key を本文の音と混ぜていないかも見る
- 旧 Mes 寄りの原稿では、〇（U+3007）を柱（○ / ◯）と誤認していないか見る。〇 は柱ではない
```

どのメディアでも使えます。順番は上の [おすすめの実務の順番](#おすすめの実務の順番) どおり、まずツールで形を見てから渡すと安心です。

形のチェックは AI の前にツールへ任せるとラクです。

- Medo: CLI `--validate` / `npm run validate`（[取り込み後の目視](06-mes-compat.md#取り込み後-medo-の目視任意)）
- カット表: `--conte --validate`（[カット表仕様](07-conte-table.md)）
- セリフ文字数: `--count` / `npm run count`（上の「セリフ文字数の照合」）

`〇` と柱の見分けは [旧 Mes 取り込みガイドの「よくあるつまずき」](06-mes-compat.md) もどうぞ。

### 旧 Mes 取り込みの手伝い

機械で直せるのは行頭の `○` / `◯` → `#` だけです（`rewriteMesCompat` / CLI `--compat`）。  
章区切りや声質の整理は人の判断なので、AI には次のように頼めます。

```
次のテキストは旧 Mes 寄りの音声原稿です。MesLang（profile: audio）へ移す提案をして。
- 行頭の ○ / ◯ は # へ（これは互換レイヤと同じ。前に空白がある ○ は行頭へ寄せてから）
- 〇（漢数字のゼロに近い形）は柱ではない。機械は直さないので、柱なら ○ / ◯ へ直す提案を「提案:」で出す
- #オープニング のような「章にしたい行」だけ == への変更案を出し、単なるト書きや柱から直した #駅前 は # のまま残す
- 本文の $ヒソヒソ声 など、話者の声に見えるものだけ :声質 への移動案を「提案:」で出す（必須ではない）
- 場の音（$雑踏）や位置（!正面）はそのまま残す。$ のない ! は話者の位置として残してよい
- 名前「セリフ」はそのままでも可（DoFlat が @ へ直す）。@名前 への手直しは任意の「提案:」まで
- &（尺・ことばの間）はそのまま残す。漫画の *間 へ直さない（音声は & 側）
- 全角の行頭記号（＠＃％ など）はそのまま残してよい（半角と同じ意味。無理に直さない）
- （ト書き）や【ト書き】の自動変換はしない
- ヘッダーの $title などはメタのまま。本文の $音 と混ぜない
- 原文と提案を分けて書き、勝手にセリフや展開を足さない
```

### アニメ字コンテ起こし

入力は字コンテ用途の **原稿** です。出力する概要は二次出力（層3）側です。

```
次の MesLang（profile: anime）を、カットごとの字コンテ概要にして。
- 入力は字コンテ下地（原稿）。完成したカット表や絵コンテ画像そのものではない
- % はカットの区切り（漫画のコマと同じ「画面の区切り」）。値はカット番号として扱う。アニメでは「コマ」と呼ばない
- 各カットについて: カメラ（^） / 尺（&） / 状況・演技（#） / 音（$） / 位置（!） / セリフ を短くまとめる
- ^ は寄り・引き・パン・手持ちなど「どう見せるか」。& は秒数の目安（&3.5s や &0:12 など）
- ? は制作ツール向けの逃げ道（bg / layout / cue / note など）。意味は仕様で固定しないので、「ツールメモ」欄に原文のまま置き、勝手にカメラやト書きへ昇格しない
- 原文にないカメラ・尺・演技は「提案:」と印をつけて分ける
- きれいな表組や絵コンテ画像は二次ツールの仕事。ここではカットの読み取りだけをする
```

入力例: [examples/animation/station-conte.mes](../../examples/animation/station-conte.mes)

### カット表への整理（二次出力の補助）

機械で同じ形を出すときは、参照パーサの `toConteTable` / `npm run conte` が本命です。  
AI に人向けの表へ直してもらうときは、次をコピーしてください。

```
次の MesLang（profile: anime）を、人が眺められるカット表（1行＝1カット）にして。
欄の対応は次のとおり（二次出力 conte-table/0.0 と同じ考え方）:
- % → カット番号（そのピースの最初の1つだけ）
- ^ → カメラ / & → 尺 / # → 演技・状況 / $ → 音 / ! → 位置 / * → ビート
- ? → ext（ツールメモ）。原文を尊重し、他の欄へ混ぜない
- @ とセリフ → 台詞（話者つき）
% が無いピースは直前のカットに足す。まだカットがなければ番号なしの行を1つ作る。
原稿そのものに表を埋め込まない。不足は「提案:」で分ける。
```

形の定義: [絵コンテ／カット表（仮）](07-conte-table.md)（[ADR 0008](../decisions/0008-conte-table-secondary.md)）

### アニメ原稿を書かせるとき

```
次のあらすじを、MesLang（profile: anime）の字コンテ下地（原稿）にして。
- 1カット＝1ピース（空行区切り）。カットの先頭に %CUT-番号。アニメでは % を「コマ」と呼ばない
- カメラは ^、尺は &、状況・演技は #、聞こえる音は $。セリフの前に @話者
- 飾りを盛りすぎない。必須はセリフと、どうしても要る % / ^ / & 程度
- 背景IDや仮レイアウト案など、仕様に無いメモは ?key value に逃がす（勝手な記号を発明しない）
- きれいなカット表・字コンテ概要・絵コンテ画像は二次の仕事。原稿の % 自体がカット表ではない
- ヘッダーに profile: anime と短い title を書く
```
