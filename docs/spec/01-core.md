# コア構造

MesLang の「骨組み」です。どのメディアでも共通の約束ごとをまとめています。

## 文字と改行

- 文字コードは UTF-8 です
- 改行は LF にそろえて扱います（CRLF でも大丈夫です）
- 全角と半角の記号は同じものとして扱います（`@` と `＠` など）

## 文書の組み立て

```
[ヘッダー]
----
[ボディ]
```

ヘッダーはなくても構いません。`----` だけの行が境目です。  
ボディは **セクション** と **ピース** でできています。

### セクション（任意）

行頭が `==` の行は、セクションの見出しです。  
章やページなど、大きめの区切りに使います。文書構造の区切りとして正式に使うのは、この形だけです。

```mes
== 第一章 / 駅前
```

旧 Mes の `#第一章` のような柱書きは、コアではふつうのト書きとして扱います。  
セクションへ寄せる変換は、互換取り込み側の任意処理です（[ADR 0003](../decisions/0003-hash-is-comment-not-section.md)）。

### ピース

**1 行以上の空行**で区切られた塊がピースです。  
脚本のうえでの、いちばん小さなまとまりだと思ってください。

```mes
@にか
こんにちは。

@こいと
こんにちは。
```

上は 2 つのピースです。

## 行の種類

ボディの、空でない行は次のいずれかです。

1. **デコレーター行** — 行頭が記号（`@` `#` `$` など）
2. **属性の続き** — 行頭が `:`（直前の記号や、そのピースに付きます）
3. **セリフ行** — 上のどれでもない行（ピースの中でつなげられます）
4. **セクション行** — `==` で始まる行

**コメントアウト**（読み飛ばす行）は、行頭 `//` です（v0）。  
`#`（ト書き）とは別ものです。旧来の `○` 柱などは、互換の速記層で扱います。

## ピースが持つ情報（イメージ）

ツールが読み取ったあと、だいたい次のようなまとまりになります。

```
Piece {
  dialogue: string          # セリフ
  decorators: Decorator[]   # 記号の行（出てきた順）
  attrs: { key: value }     # ピース直下の属性（あまり使いません）
}
```

同じ種類の記号が複数あれば、値は配列か、改行でつなぐ形にします（参照パーサは配列です）。

## 速記の橋渡し（DoFlat）

パースする前に、なじみのある書き方を正規の形へ直します。  
この処理を DoFlat（参照パーサの `doFlat`）と呼びます。

v0 で公式に含むもの:

| 入力 | 正規化後 |
|------|----------|
| `名前「セリフ」` | `@名前` + セリフ |
| `名前\tセリフ` | 同上 |
| `名前    セリフ`（空白4つ） | 同上 |

v0 では含めないもの:

| 入力 | 扱い |
|------|------|
| `#第一章`（旧柱書き） | ト書きのまま。`==` へはコアでは変換しません |

速記は、「よく知られた脚本の書き方」への橋です。新しい速記も、コアを壊さずに足せます。

## ヘッダー変数（任意）

ヘッダーの中では、`key: value` や `$key value` の形を予約しています（くわしくはこれから詰めます）。  
例: 集計で無視する文字、既定の話者、メディアプロファイル名。

```mes
profile: audio
title: 駅前の二人
----
@にか
...
```
