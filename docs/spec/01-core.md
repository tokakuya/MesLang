# コア構造

## 文字コードと改行

- UTF-8
- 改行は LF に正規化して扱う（CRLF 可）
- 全角/半角のデコレーター記号は同一視する（`@`=`＠`）

## 文書レイアウト

```
[ヘッダー]
----
[ボディ]
```

ヘッダーは省略可。`----` 単独行がデリミタ。  
ボディは **セクション** と **ピース** で構成される。

### セクション（任意）

行頭が `==` の行はセクション見出し。文書構造の区切りの **正本** はこれだけ。

```mes
== 第一章 / 駅前
```

旧 Mes の `#第一章` 柱書きはコアではト書き行のまま扱う。セクションへ寄せる変換は互換取り込み側の任意処理（[ADR 0003](../decisions/0003-hash-is-comment-not-section.md)）。

### ピース

**1 つ以上の空行**で区切られた塊がピース。脚本上の最小の意味まとまり。

```mes
@にか
こんにちは。

@こいと
こんにちは。
```

上は 2 ピース。

## 行の分類

ボディの各非空行は次のいずれか:

1. **デコレーター行** — 行頭がデコレーター記号
2. **属性継続行** — 行頭が `:`（直前デコレーターまたはピースに紐づく）
3. **セリフ行** — 上記以外（ピース内で結合可）
4. **セクション行** — `==` で始まる

**コメントアウト**（パース対象外）は行頭 `//`（v0）。`#`（ト書き）とは別。旧 `○` 柱などは互換糖衣層で扱う。

## ピースの正規形（概念）

パーサが作る論理構造:

```
Piece {
  dialogue: string
  decorators: Decorator[]   # 出現順を保持
  attrs: { key: value }     # ピース直下属性（稀）
}
```

同一種別デコレーターが複数あれば、値は配列または改行結合とする（参照パーサは配列）。

## 糖衣構文（DoFlat）

パース前に正規形へ直す変換。処理名を DoFlat（参照パーサの `doFlat`）と呼ぶ。  
公式に含めるもの（v0）:

| 入力 | 正規化後 |
|------|----------|
| `名前「セリフ」` | `@名前` + セリフ |
| `名前\tセリフ` | 同上 |
| `名前    セリフ`（空白4） | 同上 |

含めないもの（v0）:

| 入力 | 扱い |
|------|------|
| `#第一章`（旧柱書き） | ト書きのまま。`==` へはコアで変換しない |

糖衣は「よく知られた脚本記述」への橋。新しい糖衣はコアを壊さず追加できる。

## ヘッダー変数（任意）

ヘッダー内の `key: value` または `$key value` 形式を予約する（詳細は後続）。  
例: 集計時に無視する文字、デフォルト話者、メディアプロファイル名。

```mes
profile: audio
title: 駅前の二人
----
@にか
...
```
