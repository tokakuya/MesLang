# 絵コンテ／カット表（二次出力・仮）

ステータス: **実験中**（`conte-table/0.0`）  
読者: ツール作者・AI。著者はふだん [アニメプロファイル](03-media-profiles.md#アニメprofile-anime) の原稿だけで十分です。

## これは何ですか

MesLang の原稿（字コンテ下地）からつくった **Medo** を、カット表っぽい行の並びに直したものです。  
きれいな絵コンテの組版そのものではありません。読みやすさは、ここから先の二次ツールの仕事です。

三層で言うと、原稿＝字コンテ下地（層1）→ Medo（層2）→ **このカット表（層3・二次出力）** です。  
「字コンテ下地」と「カット表／字コンテ概要」の呼び分けは [用語集](05-glossary.md#原稿と二次出力まぎらわしいことば) をどうぞ。  
原稿のなかの `%`（カット）と、この二次出力の「カット表」も別ものです（[コマとカット](05-glossary.md#コマとカットまぎらわしいことば)）。方針は [ADR 0008](../decisions/0008-conte-table-secondary.md) にあります。

## どう組み立てるか

1. Medo のピースを順に見ます
2. `%`（kind `frame`）があるピースで、**新しいカット行**を始めます。カット番号は、そのピースの最初の `%` の値です
3. `%` がないピースは、直前のカット行に足します（まだカットがなければ、番号なしの行を1つ作ります）
4. 同じピース内の記号は、次の欄へ分けます

| 原稿の記号 | カット行の欄 |
|------------|--------------|
| `%` | `cut`（最初の1つだけ。あとの `%` はいまは無視） |
| `^` | `camera` |
| `&` | `timing` |
| `#` | `action` |
| `$` | `sound` |
| `!` | `position` |
| `*` | `beat` |
| `?` | `ext` |
| `@` + セリフ | `dialogues`（話者と本文） |

## JSON の形（仮）

```json
{
  "version": "conte-table/0.0",
  "title": "駅前の二人（字コンテ下地）",
  "profile": "anime",
  "cuts": [
    {
      "cut": "CUT-001",
      "camera": ["広角 / ゆっくりパン"],
      "timing": ["4s"],
      "action": ["改札前の雑踏。にかがフレームイン"],
      "sound": ["環境音メイン"],
      "position": [],
      "beat": [],
      "ext": ["bg station_plaza_evening", "layout ワイド導入"],
      "dialogues": []
    }
  ]
}
```

機械向けの定義は [schema/conte-table.schema.json](../../schema/conte-table.schema.json) です。  
参照パーサでは `toConteTable` と CLI の `--conte` で同じ形を出せます。

形チェックは `validateConteTable`（Medo の `validateMedo` と同じく、小さな参照実装。ajv などは使いません）です。  
ここでも見るのは **箱の名前と型** だけです（カット割りやカメラの良し悪しは見ません → [用語集](05-glossary.md#形チェックと目視まぎらわしいことば)）。  
CLI では `--conte --validate` で、まず Medo、つづけてカット表の形を見ます。

### 形チェックが見る縁（よく迷うところ）

手組みの JSON や、変換の途中形を見るときの目安です。

| 縁 | 形チェック | 注 |
|----|------------|-----|
| `cut: ""`（番号なし） | **通る** | `%` より前のピースから始まった行。空文字も正しい箱の値です |
| `camera` など配列が `[]` | **通る** | その欄が空なだけ。セリフなしカットの `dialogues: []` も同じ |
| `cuts: []` | **通る** | ピースが無い原稿から変換したとき |
| ルートやカット行の余分なキー | **弾く** | schema の `additionalProperties: false` と同じ |
| `camera` が文字列や数値の配列 | **弾く** | 箱は「文字列の配列」だけ。中身の良し悪しは見ません |
| `dialogues[].speaker` / `text` 以外 | **弾く** | 話者の attrs は Medo 側。カット表行には載せません |

番号なしの行は誤りではありません。  
「カット番号が空だから品質が悪い」と形チェックが言っているわけではない、というだけです → [用語集](05-glossary.md#カット表の形チェックの縁まぎらわしいことば)。

## やらないこと（いま）

- 原稿への表レイアウトの強制
- カットとカメラの硬い1対1紐づけ（複数 `^` / `&` は配列のまま残します）
- 絵コンテ画像の生成や配置（参考画像は漫画の [ADR 0004](../decisions/0004-manga-reference-images.md) と同様、必要なら二次成果物）
