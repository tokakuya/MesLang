# MesLang の哲学

Mes から引き継ぎ、MesLang で明示する設計原則です。仕様変更時もここに戻ります。

## 1. 思考を阻害しない

脚本家の想起順は一定ではない。セリフが先か、状況が先か、音が先か——人によって、場面によって違う。

だからデコレーターは **セリフの前にも後ろにも置ける**。順序を強制しない。

## 2. 書きやすさと読みやすさを分離する

速記は読みにくくなりやすい。MesLang は「書くための原稿」に寄せる。

「読むための台本 / ネーム / 字コンテ」は二次ツールの責務とする。原稿そのものに組版や見栄えを求めない。

## 3. 必須情報をほぼゼロにする

セリフだけでも合法。装飾は必要なときだけ足す。  
後から音響担当が `$` を足す、ネーム段階で `%` を足す、といった分担が自然にできる。

## 4. 記号速記と丁寧な字句を両立する

| モード | 例 | 用途 |
|--------|----|------|
| 記号速記 | `@にか` `%3` `$足音` | フローを止めない執筆 |
| 属性 | `@にか :表情 泣` | 機械が分離したい意味 |
| 字句デコレーション | `#少し呆れた感じで、視線を逸らす` | 人間と AI が読める意味付け |

記号は入口、字句は意味の本体。どちらか一方に寄せすぎない。

## 5. 人間・パーサ・AI の三者可読

- **人間**: タイピング負荷が低い、思い出しやすい記号
- **パーサ**: 行頭記号と空行区切りで決定的に構造化できる
- **AI**: 記号の意味は仕様書に固定しつつ、`#` や属性値は自然言語で豊かに書ける

AI に「推測で補完させる」のではなく、「書いた意味を読み取らせる」ことを優先する。

## 6. 実験を前提に、変更を安くする

このプロジェクトは実験的である。破壊的変更を恐れない。

代わりに:

- 仕様は小さな文書に分割する
- 変更は ADR に残す
- 参照パーサは「正しさの錨」であり、製品級の互換保証はしない
- メディア固有機能はプロファイルとしてコアから外に出す

## 7. メディアはプロファイルで伸ばす

コアは「ピース + デコレーター + 属性」。  
漫画のコマ、アニメのカット、VN の分岐は **プロファイル** として後付けする。コアを肥大化させない。
