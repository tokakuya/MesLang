# MesLang の哲学

Mes から引き継ぎ、MesLang でも大切にしている考え方です。  
仕様を変えるときも、ここに戻って確認します。

## 1. 思考を止めない

脚本を書くとき、思い浮かぶ順番は人それぞれです。  
セリフが先のこともあれば、状況や音が先のこともあります。

だから記号（デコレーター／行頭記号）は、**セリフの前にも後ろにも置けます**。  
順番は強制しません。呼び分けは [用語集](spec/05-glossary.md#デコレーターと行頭記号まぎらわしいことば) をどうぞ。

## 2. 書きやすさと読みやすさを分ける

速記は、どうしても読みにくくなりがちです。  
MesLang は「書くための原稿」に寄せます。

「読むための台本 / ネーム / 字コンテ / カット表」は、二次ツールの仕事にします。  
原稿そのものに、きれいな組版や見栄えは求めません。

整理すると、**原稿 → Medo（中間データ）→ カット表などの二次出力** の三層です（[用語集](spec/05-glossary.md#三層原稿--medo--カット表)）。

## 3. 必須の情報は、ほぼゼロ

セリフだけでも大丈夫です。飾りは、必要なときだけ足します。  
あとから音響担当が `$` を足す、ネームの段階で `%` を足す、といった分担が自然にできるようにしています。

## 4. 記号の速さも、ことばの丁寧さも大切にする

| 書き方 | 例 | 向いていること |
|--------|----|----------------|
| 記号でさっと | `@にか` `%3` `$足音` | 流れを止めない執筆 |
| 属性 | `@にか :表情 泣` | 機械にも分けてほしい意味 |
| ことばで丁寧に | `#少し呆れた感じで、視線を逸らす` | 人にも AI にも伝わる意味付け |

記号は入口、ことばは意味の本体です。どちらか一方に寄せすぎません。

## 5. 人・ツール・AI、三者とも読めるように

- **人**: 打ちやすく、思い出しやすい記号
- **ツール（パーサ）**: 行頭の記号と空行で、はっきり構造化できる
- **AI**: 記号の意味は仕様で固定しつつ、`#` や属性の値は自然なことばで豊かに書ける

AI に「推測で補ってもらう」より、「書いた意味をきちんと読んでもらう」ことを優先します。

## 6. 実験前提で、変更を安くする

このプロジェクトは実験的です。大きく変えることも恐れません。

そのかわり:

- 仕様は小さな文書に分けます
- 変更は ADR に残します
- 参照パーサは「正しさの目印」であり、製品並みの互換保証はしません
- メディアごとの機能はプロファイルとして、コアの外に出します

## 7. メディアごとの違いは、プロファイルで伸ばす

コアは「ピース + デコレーター + 属性」です。  
漫画のコマ、アニメのカット、VN の分岐などは **プロファイル** としてあとから足します。コアを太らせすぎません。
