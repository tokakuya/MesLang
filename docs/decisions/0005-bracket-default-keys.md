# ADR 0005 — ブラケット糖衣の既定キー順（v0）

- 日付: 2026-07-25
- ステータス: Accepted
- 関連: [ADR 0002](0002-attribute-syntax.md)、`docs/spec/02-decorators.md`、参照パーサ `extractInlineAttrs`

## 文脈

`@名前[泣][前傾]` 糖衣は ADR 0002 で許可済みだが、2 個目以降のキー対応が「プロファイルで拡張（未解決）」のままだった。  
参照パーサはすでに「1 個目＝表情、2 個目＝姿勢」で動いており、仕様書と実装の用語が揃っていなかった。

## 決定

v0 の **既定**（プロファイル未指定・上書きなし）は次とする。

| ブラケット位置 | 正規化先キー |
|----------------|--------------|
| 1 個目 | `表情` |
| 2 個目 | `姿勢` |
| 3 個目以降 | `表情2`, `表情3`, …（3 個目が `表情2`） |

注:

1. 著者向け文書では属性キー **姿勢** を正とする。通称の「ポーズ」はキー名にしない（英語エイリアス `pose` は別途書いてよい）。
2. プロファイルやヘッダーによる対応表の上書きは **将来拡張** のまま残す（本 ADR では定めない）。
3. 明示の `:key value` がある場合はブラケットよりそちらを優先できる（現状の参照パーサは同一デコレーター上でマージ）。

## 結果

- 良い: 仕様・用語集・参照パーサが同じ対応表を指す
- 悪い: 3 個目以降の意味は弱い（表情の追加スロット）。必要なら後でプロファイル表へ逃がす
- フォロー: audio/manga 向けの拡張対応表は backlog に残す
